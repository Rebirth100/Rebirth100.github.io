C 语言给程序员很大的自由，也要求程序员自己负责边界检查。

读越界和写越界

数组越界分两种：读越界和写越界。

读越界，是从不属于数组的位置读取数据。

这会读取数组外面的内存。读到什么不确定，可能是旧数据，也可能是别的变量的值。

写越界，是向不属于数组的位置写入数据。

写越界通常更危险。因为它可能改掉其他变量，破坏程序内部状态。

看一个例子：

在某些环境中，x 的值可能被影响。在另一些环境中，看起来没有变化。还有一些情况下，程序可能直接崩溃。

这不是说某个结果才是正确的，而是代码已经进入了不可预测状态。

数组越界属于未定义行为。简单理解就是：一旦发生，程序结果没有保证。

为什么C语言不自动检查越界

很多语言会在数组越界时直接报错，比如访问不存在的位置，程序会告诉你下标超出范围。

C 语言通常不会主动帮你做这种检查。

原因和 C 语言的设计目标有关。C 语言强调效率、底层控制和灵活性。数组访问本质上接近地址计算：

只要你给了下标，程序就按这个公式去算地址。至于这个地址是不是还在数组内部，C 语言很多时候不会替你判断。

这样做的好处是效率高，开销小。

坏处是安全性要由程序员自己负责。

所以写 C 程序时，不能依赖语言自动保护你。数组下标是否安全，必须自己检查。

本章小结

数组越界就是访问了数组合法范围之外的位置。

长度为 n 的数组，合法下标是 0 到 n - 1。

arr[n] 不是最后一个元素，而是越界位置。

数组越界分为读越界和写越界。读越界可能读到垃圾数据，写越界可能破坏其他变量。

C 语言通常不会自动检查数组越界，所以程序员必须自己控制边界。
