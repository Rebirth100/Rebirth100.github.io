C 语言文件操作与结构体模块学习笔记

一、标准 IO 基础

1.1 标准 IO 概念

  • 标准 IO 是 C 标准库统一封装的输入输出接口，跨平台
  • 核心数据结构：FILE 结构体（标准 C 预定义，存储文件位置、地址、状态等信息）
  • 不要随意修改 FILE 结构体内容，否则库无法正常使用

1.2 三个标准流

流 含义 默认设备 缓冲区
stdin 标准输入 键盘 有
stdout 标准输出 显示器 有（遇换行或满刷新）
stderr 标准错误 显示器 无缓冲，直接输出

错误提示优先用 stderr，避免缓冲区未刷新导致错误信息看不到。

1.3 CPU 取数层级

  • auto：默认变量类型，存储在内存
  • register：建议编译器放到寄存器，提升访问速度，不能取地址

2.1 fopen / fclose

打开失败必须检查

2.2 打开模式

模式 含义 文件不存在 文件存在
r 只读 报错 打开，从头读
w 只写 创建 清空原有内容
a 追加 创建 在末尾追加
r+ 读写 报错 打开，从头读写
w+ 读写 创建 清空原有内容
a+ 读追加 创建 在末尾追加，可读
  • 加 t：文本模式（默认，如 rt）
  • 加 b：二进制模式（如 rb、wb）
  • r/w/a 三类基础模式互斥，不可同时使用

5.4 格式匹配要点（重要）

  • 写入和读取的格式必须严格一致（宽度、分隔符、顺序）
  • 写入时设置固定宽度（如 %20s、%4d），读取时用相同格式
  • 格式不匹配会导致数据错乱、读取失败
  • fscanf 不支持精度格式符（如 %.2d）
  • 写入后必须 fclose，否则数据可能留在缓冲区未写入磁盘
  • 不要提前释放结构体内存再写入，会导致乱码

6.4 文本 vs 二进制

对比项 文本模式（fprintf/fscanf） 二进制模式（fwrite/fread）
数据转换 需要，人可读 不需要，内存原样写入
文件内容 可直接查看 乱码，需程序解析
效率 较低（有转换开销） 高
适用场景 配置文件、日志 大批量结构体数据

九、通用数据结构设计（作业）

9.1 现有链表的问题

  • 多数实现只针对特定节点类型，无法复用
  • 换一种数据类型就要重写增删改查

9.2 三种通用实现方案

方案 特点 适用场景
带数据域节点 节点含数据域+指针域，头指针+计数+容量 实现简单
无数据域节点 节点仅指针域，链表结构作为自定义数据首成员 通用性最强，90%场景选用
动态数组 指针数组托管数据，有效计数+容量，支持自动扩容 需随机访问

作业：三选一实现通用链表/动态数组，支持任意类型数据，次日提交。

十、命令行参数

  • argc：参数个数（含程序名）
  • argv[0]：程序本身路径/名称
  • argv[1] 起：用户传入的参数
  • 使用前必须校验 argc 是否符合预期
