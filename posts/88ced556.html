一、线程属性与分离状态

1.1 线程属性概述

在 pthread_create 创建线程时，第二个参数 attr 用于指定线程属性。之前我们一直传 NULL 使用默认属性。通过 pthread_attr_t 可以自定义线程的各种属性。

可设置的线程属性包括：

属性 说明
分离状态（detachstate） joinable（可结合）或 detached（已分离）
栈大小（stacksize） 线程栈的大小
栈地址（stackaddr） 线程栈的起始地址
竞争范围（contentionscope） 进程级或系统级竞争
继承调度（inheritsched） 是否继承创建者的调度策略
调度策略（schedpolicy） SCHED_OTHER / SCHED_FIFO / SCHED_RR
调度参数（schedparam） 调度优先级等参数

1.2 核心函数

pthread_attr_init — 初始化属性对象

  • 初始化线程属性对象为默认值
  • 成功返回 0，失败返回错误号

pthread_attr_destroy — 销毁属性对象

  • 销毁线程属性对象，释放资源
  • 使用完毕后必须调用

pthread_attr_setdetachstate — 设置分离状态

  • detachstate 取值：
    • PTHREAD_CREATE_JOINABLE：可结合（默认），需要 pthread_join 等待
    • PTHREAD_CREATE_DETACHED：已分离，线程退出后自动回收资源，不能被 join

pthread_attr_getdetachstate — 获取分离状态

1.3 可结合线程 vs 已分离线程

对比项 可结合线程（joinable） 已分离线程（detached）
创建方式 默认，或显式设置 JOINABLE 设置 DETACHED，或调用 pthread_detach
退出后资源 需调用 pthread_join 才回收 退出后自动回收
能否获取返回值 可以，通过 pthread_join 不能，资源已自动释放
适用场景 需要等待线程完成、需要返回值 后台任务、不需要等待的工作线程

注意：一个线程不能同时被 join 和 detach。对已分离的线程调用 pthread_join 会失败。

二、线程互斥与互斥锁

2.1 为什么需要互斥

多个线程共享进程的地址空间，当多个线程同时操作同一个共享资源（如全局变量、文件、设备）时，可能会产生竞态条件（Race Condition），导致结果不确定或错误。

典型场景：火车票抢票

一列火车只剩 5 张票，同时有 10 个人在抢票。如果没有互斥机制，可能出现： - 两个人同时看到还有 5 张票 - 两个人同时扣减，导致票数变成负数或超卖 - 需要保证一个人在操作票数时，其他人不能操作

这就是线程互斥（Mutual Exclusion）：同一时刻只允许一个线程访问共享资源。

2.2 竞态条件演示

原因分析： global_count++ 不是原子操作，它分为三步： 1. 从内存读取 global_count 的值到寄存器 2. 寄存器值加 1 3. 将结果写回内存

如果两个线程在第 1 步读取了相同的值，各自加 1 后写回，就会丢失一次累加。

2.3 互斥锁（Mutex）

互斥锁（Mutex，Mutual Exclusion Lock）是最常用的线程同步机制。它保证同一时刻只有一个线程能持有锁，从而保护共享资源的访问。

2.5 临界区与锁的粒度

  • 临界区（Critical Section）：被互斥锁保护的代码段，同一时刻只能有一个线程执行
  • 锁的粒度：临界区的大小
    • 粒度太大：并行度低，性能差
    • 粒度太小：锁开销大，可能无法正确保护资源
  • 原则：临界区应尽可能小，只包含必须互斥的操作

2.6 火车票抢票模拟

2.7 互斥锁的属性

递归锁（PTHREAD_MUTEX_RECURSIVE）： 同一线程可以多次加锁，必须对应次数解锁。适用于函数嵌套调用中都需要同一把锁的场景。

三、死锁与自旋锁

3.1 死锁的概念

死锁（Deadlock） 是指多个线程在执行过程中，因争夺资源而造成的一种互相等待的现象，若无外力作用，它们都将无法继续执行。

死锁的典型场景： - 线程 A 持有锁 1，等待锁 2 - 线程 B 持有锁 2，等待锁 1 - 两个线程都不释放自己持有的锁，都在等待对方释放，形成死锁

死锁产生的四个必要条件（ Coffman 条件）：

条件 说明
互斥条件 资源同一时刻只能被一个线程持有
持有并等待 线程持有至少一个资源，同时等待其他线程持有的资源
不可剥夺 资源只能由持有者主动释放，不能被强行剥夺
循环等待 存在一个线程循环链，每个线程都在等待下一个线程持有的资源

3.2 死锁的预防与避免

破坏死锁的四个必要条件之一即可预防死锁：

  1. 破坏互斥条件：允许资源同时被多个线程访问（但很多资源必须互斥，不现实）
  2. 破坏持有并等待：线程一次性申请所有需要的资源，申请不到就不持有任何资源
  3. 破坏不可剥夺：线程申请不到资源时，主动释放已持有的资源
  4. 破坏循环等待：对资源进行编号，线程必须按编号顺序申请资源

实际开发中常用的方法：

  • 按固定顺序加锁：所有线程都按相同的顺序申请锁，避免循环等待
  • 使用 trylock：加锁失败时不阻塞，释放已持有的锁后重试
  • 设置超时：加锁时设置超时时间，超时后释放资源重试
  • 减少锁的使用：用原子操作、无锁数据结构替代锁

3.5 线程意外取消导致的死锁

线程在持有锁的过程中被意外取消（如 pthread_cancel），如果没有正确处理，锁将永远不会被释放，导致其他线程永远等待，形成死锁。

解决方案：使用线程取消清理函数（cleanup handler）

pthread_cleanup_push 和 pthread_cleanup_pop 必须成对出现： - pthread_cleanup_push(handler, arg)：注册清理函数 - pthread_cleanup_pop(execute)：弹出清理函数 - execute = 0：只弹出，不执行 - execute = 1：弹出并执行清理函数

线程被取消时，会按注册的逆序依次执行所有 cleanup handler，确保资源被正确释放。

3.6 自旋锁（Spinlock）

自旋锁是另一种锁机制。当线程尝试获取锁失败时，不会阻塞睡眠，而是循环等待（忙等），不断检查锁是否可用。

自旋锁 vs 互斥锁：

对比项 互斥锁（mutex） 自旋锁（spinlock）
等待方式 阻塞睡眠，让出 CPU 忙等循环，占用 CPU
上下文切换 有（睡眠/唤醒） 无
适用场景 临界区较长、等待时间长 临界区极短、等待时间短
开销 睡眠/唤醒开销大 忙等浪费 CPU
死锁风险 有 有（且更危险，忙等占满 CPU）

3.7 带超时的锁（自旋锁的超时思想）

自旋锁的一个重要应用场景是带超时的锁：如果持有锁的线程执行时间超过预期（如死锁、卡死），可以主动释放锁让其他线程继续。

思路： 1. 评估任务正常执行所需时间 2. 设置超时阈值（如正常时间的 1.5 倍） 3. 持有锁的线程如果超过阈值还未释放，系统主动解锁

这种机制在实际生产环境中常用于防止单个异常任务拖垮整个系统。

3.8 锁的选择建议

场景 推荐锁
临界区较长（>几微秒） 互斥锁（mutex）
临界区极短（<几微秒） 自旋锁（spinlock）
需要递归加锁 递归互斥锁（PTHREAD_MUTEX_RECURSIVE）
跨进程同步 进程共享互斥锁 / 信号量
避免死锁 按顺序加锁 + trylock + 超时

四、面试考点汇总

4.1 线程属性

  1. 线程有哪些属性？如何设置？
    • 通过 pthread_attr_t 设置，包括分离状态、栈大小、调度策略、竞争范围等
    • pthread_attr_init 初始化，pthread_attr_setxxx 设置，创建线程后 pthread_attr_destroy 销毁
  2. joinable 和 detached 线程的区别？
    • joinable：需要 pthread_join 等待，可获取返回值，资源由 join 释放
    • detached：退出后自动回收资源，不能被 join，适用于后台任务
  3. 如何将线程变为分离状态？
    • 创建时设置属性：pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED)
    • 运行时调用：pthread_detach(tid) 或 pthread_detach(pthread_self())

4.2 线程互斥

  1. 什么是竞态条件？举例说明？
    • 多个线程同时访问共享资源，导致结果不确定。如多线程累加全局变量，结果小于期望值
  2. 互斥锁的工作原理？
    • 同一时刻只有一个线程能持有锁，其他线程尝试加锁时阻塞等待
    • 保护临界区代码，确保共享资源的互斥访问
  3. mutex 和 semaphore 的区别？
    • mutex：互斥锁，只有 0/1 两种状态，用于互斥，必须由持有者解锁
    • semaphore：信号量，可以有多个资源计数，用于同步和互斥，可由其他线程释放
  4. 什么是临界区？锁的粒度过大或过小有什么问题？
    • 临界区：被锁保护的代码段
    • 粒度过大：并行度低，性能差
    • 粒度过小：锁开销大，可能无法正确保护资源
  5. pthread_mutex_lock 和 pthread_mutex_trylock 的区别？
    • lock：阻塞等待，直到获取锁
    • trylock：非阻塞，获取失败立即返回（返回 EBUSY）

4.3 死锁

  1. 什么是死锁？死锁产生的四个必要条件？
    • 多个线程因争夺资源互相等待，都无法继续执行
    • 四个条件：互斥、持有并等待、不可剥夺、循环等待
  2. 如何预防和避免死锁？
    • 按固定顺序加锁（破坏循环等待）
    • 使用 trylock，失败则释放已有锁重试
    • 设置超时时间
    • 一次性申请所有资源（破坏持有并等待）
  3. 线程被取消时如何避免死锁？
    • 使用 pthread_cleanup_push / pthread_cleanup_pop 注册清理函数
    • 线程被取消时自动执行清理函数释放锁
  4. 什么是自旋锁？和互斥锁的区别？
    • 自旋锁：获取失败时忙等循环，不睡眠
    • 互斥锁：获取失败时阻塞睡眠，让出 CPU
    • 自旋锁适用于临界区极短的场景，互斥锁适用于临界区较长的场景
  5. 递归锁是什么？适用场景？
    • 同一线程可以多次加锁，必须对应次数解锁
    • 适用于函数嵌套调用中都需要同一把锁的场景，避免自己锁死自己
