物联网面试题汇总

1. C++面向对象三大特性理解

封装：将数据和操作方法封装在一起，一般数据为private，可以被继承使用的为protected，对数据的操作一般通过函数实现，对外可以使用的函数为public，不对外使用的函数但可以被子类使用的函数为protected，只能为本类使用的函数为private。

继承：一个类继承另外一个类的属性和方法，子类只能访问父类的protected和public属性和方法，无法访问父类的private属性和方法。注意菱形继承问题，菱形继承可能会导致二义性、冗余和潜在的维护问题。

多态：可以以统一的方式使用不同对象，通过虚函数实现，在派生类中重写该方法以改变其行为。

2. 静态多态和动态多态

静态多态是通过函数重载和模板实现的，编译期就确定了，执行效率高。

动态多态是通过虚函数加继承实现的，多了一个vtable，运行时动态绑定函数，执行效率低。

3. C++编译器提供的四个默认函数

默认无参构造函数：如果用户定义了一个构造函数，不管有参还是无参，编译器就不生成默认构造函数了。实际开发中通常显式定义构造函数，不然编译器会生成默认的构造函数。

拷贝构造函数和拷贝赋值运算符：这两个一般不使用，使用时显式定义出来，不使用时加上 = delete。

析构函数：最好显式定义出来，不让编译器默认生成。

4. 函数重载和函数重写的区别

函数重载是指在函数名相同，但参数不同的函数，不参考返回值。

函数重写是在继承中产生的，派生类重新定义了基类的虚函数，函数名、参数、返回值必须完全一样。为了防止出错，一般在派生类的函数后面加上 override 关键字，让编译器帮忙检查是否出错。

5. 对C++面向对象编程思想的理解

面向对象的思想把属性和方法封装在一起，不会出现面向过程C语言那样大量全局变量的情况。面向对象还增加了访问权限，大大增加了操作安全。继承增加了模块功能的复用，多态实现了不同子类统一的访问接口。

6. new delete malloc free区别

malloc/free 只是用来分配内存、释放内存（需要手动计算大小）。new/delete 不但可以分配内存、释放内存（不需要手动计算），还可以调用构造函数和析构函数。new 一个数组时不要忘了 delete 时加 []，尽量使用 new/delete。

malloc：返回 void*，需强制类型转换；new：返回对应类型指针，无需转换。

malloc：仅分配内存，不初始化，内容为随机值；new：可直接初始化（new int(5)），对象会自动调用构造函数。

7. 指针和引用传参的时候区别

指针可以传动态分配的资源，但使用指针时要判断是否为空。能用引用的地方尽量使用引用。

8. STL下常见的容器

vector： 特点：动态数组，支持随机访问，插入和删除操作会导致内存重新分配。 用法：std::vector<T> vec;，其中 T 为元素类型。

deque： 特点：双端队列，支持在头部和尾部进行插入和删除操作，内部实现为分段连续内存。 用法：std::deque<T> deq;，其中 T 为元素类型。

list： 特点：双向链表，支持在任意位置进行插入和删除操作，不需要内存重新分配。 用法：std::list<T> lst;，其中 T 为元素类型。

set： 特点：有序集合，内部实现为红黑树，支持快速查找、插入和删除操作，元素自动排序且不重复。 用法：std::set<T> st;，其中 T 为元素类型。

multiset： 特点：有序集合，内部实现为红黑树，支持快速查找、插入和删除操作，元素自动排序，允许重复。 用法：std::multiset<T> mst;，其中 T 为元素类型。

map： 特点：有序映射，内部实现为红黑树，支持快速查找、插入和删除操作，键值对形式存储，键自动排序且不重复。 用法：std::map<K,V> mp;，其中 K 为键类型，V 为值类型。

multimap： 特点：有序映射，内部实现为红黑树，支持快速查找、插入和删除操作，键值对形式存储，键自动排序，允许重复。 用法：std::multimap<K,V> mmp;，其中 K 为键类型，V 为值类型。

unordered_set： 特点：无序集合，内部实现为哈希表，支持快速查找、插入和删除操作，元素不重复。 用法：std::unordered_set<T> uSt;，其中 T 为元素类型。

unordered_multiset： 特点：无序集合，内部实现为哈希表，支持快速查找、插入和删除操作，允许重复。 用法：std::unordered_multiset<T> ummst;，其中 T 为元素类型。

unordered_map： 特点：无序映射，内部实现为哈希表，支持快速查找、插入和删除操作，键值对形式存储，键不重复。 用法：std::unordered_map<K, V> um;，其中 K 为键类型，V 为值类型。

unordered_multimap： 特点：无序映射，内部实现为哈希表，支持快速查找、插入和删除操作，键值对形式存储，允许重复。 用法：std::unordered_multimap<K, V> umm;，其中 K 为键类型，V 为值类型。

9. 智能指针

智能指针包括：shared_ptr 共享智能指针、unique_ptr 唯一性指针、weak_ptr 弱引用指针。weak_ptr 是为了配合 shared_ptr 解决循环引用问题。weak_ptr 使用时先 lock 出一个 shared_ptr，但要判断 shared_ptr 指针是否为空。推荐使用 unique_ptr，能用 unique_ptr 的就使用 unique_ptr。

10. 浅拷贝和深拷贝的区别

浅拷贝：只拷贝指针，指向的内容没有被拷贝，共享指向的内容。优点是拷贝速度快，占用空间小；缺点是指向的内容改变时，都会受到影响。

深拷贝：指向的内容会被完全拷贝。优点是内容独立，修改时互不影响；缺点是拷贝速度慢，占用空间多。

写时拷贝技术充分利用了这两种拷贝的优点：先浅拷贝，速度快，占用空间小；写的时候再深拷贝，修改内容互不影响。

11. C++类型的强制转换

静态转换 static_cast：显式转换，不安全。

动态转换 dynamic_cast：安全的基类向派生类转换，转化不成功会返回空指针，运行时检查是否能转换成功，只能用在有多态的基类与派生类之间。

常量转换 const_cast：去常量化，去掉了常量特性就增加了安全风险。

重新解释转换 reinterpret_cast：不同类型指针之间的转换，只能用在指针类型，没有任何安全监测，所以很不安全，谨慎使用。

用得最多的是 dynamic_cast，因为它能做安全检查。

12. 内存分区 static变量放在什么区

静态区。生命周期较长，一般会到程序结束时才释放。函数内的 static 变量虽然作用域范围是在函数内，但其生命周期很长，直到程序结束。

13. 多态具体实现

代码方面：基类有虚函数，纯虚函数也可以，派生类重新实现基类虚函数。为了防止出错，派生类重新声明虚函数时加上 override 关键字。如果父类有纯虚函数，派生类只有实现了所有基类纯虚函数才能被实例化。

编译器方面：编译器会生成一个虚函数表 vtable，用来在多态时指向派生类的函数。vtable 也支持了动态转换 dynamic_cast 的实现。

14. inline内联函数

编译器对内联函数做了优化，把函数体和局部变量放到了函数调用处，这样调用函数不需要再跳转到可能较远的地址进行函数调用了，提高了函数调用效率。

需要注意的是，较大的函数、出现循环的函数、递归函数等不适合内联，否则可能程序的总代码量增大，消耗更多的资源，反而降低了效率。有些编译器会把一些简单函数自动内联，不符合内联要求的函数，即使加了 inline 关键字，也会忽略，不进行内联。

作用：减少函数的开销、提高代码的执行速度、优化代码的可读性、减少函数调用带来的空间开销。

15. 堆和栈的区别

  1. 管理者不同：栈是由操作系统管理的，主要用在函数调用上，把函数地址、函数参数和局部变量压栈；堆是由开发者申请和释放的。
  2. 大小不同：栈的空间不大，64位系统一般也就几兆，如果函数局部变量较大会出现 bug，有时还不容易查找。堆的空间比较大。
  3. 数据结构不同：栈数据结构的特点是先进后出。
  4. 存放内容不同：栈存放函数地址、函数参数、局部变量、返回值和寄存器内容等，这些都是操作系统操作的；堆可以存放任意内容。
  5. 分配效率不同：在硬件层上支持栈的操作，很大地提高了效率。堆使用函数库，在软件层次上支持，需要复杂的算法维护，还有容易出现内存碎片问题，效率较低。

18. 用的C++多还是C多

第一个版本：使用的 C++ 多，因为本身支持面向对象，还有各种工具支持，比如标准模板库 STL、智能指针等，很大地提高开发维护效率。

20. 什么是函数对象

可以当函数使用的类，需要实现 operator() 运算符重载。因为对象可以有属性，可以存储一些数据，比如一些状态数据。函数对象和 lambda 功能类似。

21. 重载是不是多态

属于静态多态，编译型多态，在编译的时候决定了调用关系，执行效率高。

而动态多态是通过虚函数加继承实现的，多了一个 vtable，运行时动态绑定函数，执行效率低。

22. 父类的对象转成子类的对象可以吗，为什么

不可以直接安全地转换。子类对象通常比父类对象包含更多的成员和方法。父类对象在创建时只构造了父类部分，子类新增的成员并没有被构造或初始化。如果把父类对象强制当成子类对象使用，访问子类特有的成员或方法时，这些部分是不确定的，可能导致未定义行为。若通过基类指针/引用向下转型，应使用 dynamic_cast 做运行时检查；只有该指针/引用实际指向子类对象时，转换才安全。

23. 容器的list和map有什么区别

list 是线性的链表，允许存放重复值；map 存放键值对，键是唯一的不能重复，使用红黑树数据结构实现，查找速度快。

24. 结构体和联合体的区别

结构体依次存储所有成员，结构体所占内存是所有成员变量大小总和。如果有内存对齐，char 类型可能要占 4 个字节。为了减少占用的内存，多个 char 类型放在一起定义，如果被 int 隔开的话对齐时会占用更多的内存。

联合体：所有成员的内存共享一块内存，内存大小是最大成员所需内存。在 C++17 中可以使用 variant 替代联合体，更加安全。

27. 构造函数能作为虚函数吗？

构造函数不能作为虚函数，但析构函数可以作为虚函数，而且尽量把析构函数定义为虚函数，防止析构函数不正确的调用而导致资源不能正常释放。比如，delete 一个指向派生类的基类类型指针，如果析构不是虚函数，调用基类的析构；如果析构是虚函数，会查找虚函数表 vtable，调用派生类的析构函数。

28. 创建和销毁对象时，基类和派生类构造和析构的调用顺序

创建基类对象时，构造函数顺序：先构造基类再构造子类；析构函数顺序相反：先析构子类再析构基类。通过这些构造和析构的顺序，注意使用时资源的创建和释放顺序。

29. 数组和链表的区别

数组是连续内存，链表的内存是不连续的，一块块的。数组占用内存少，链表占用内存多，因为链表每个节点要存放前后指针信息。数组随机访问效率很高，链表随机访问效率低。数组尾部添加、删除效率高，其它位置添加、删除效率低。链表任意位置添加、删除效率高。

30. STL标准库用vector替代动态数组

vector 是一个模板，支持很多类型，可以动态扩展，有很多接口，方便和安全地使用数据。

31. 野指针形成原因及避免方法

  1. 指向了已经释放的空间。避免：释放完空间后及时给指针变量赋 nullptr。
  2. 没有初始化。避免：养成好的习惯，指针变量定义完后马上指向一个空间，或者赋 nullptr。
  3. 越界访问。避免：边界检查，尽量不要进行指针的运算。
  4. 指针变量被覆盖，找不到了，无法使用。避免：养成好的习惯，使用前先检查被赋值的指针变量是否为空，如果为空，直接赋值；如果不为空，看是否需要释放，还是把指针值赋给其它指针来保存。

32. TCP和UDP区别

TCP： 1. 面向连接的，有连接的，创建时有三次握手。 2. 数据的特点是数据流，没有报文概念，会出现“粘包”现象。 3. 数据不会丢失。 4. 开销大，因为需要发送校验。 5. 数据有序，接收的数据顺序和发送的数据顺序一样。 6. 全双工通信。

解决“粘包”： - 协议中规定一段包头字段，用来区分是否为一个包的开始； - 协议中有包长字段； - 两者结合。

UDP： 1. 无连接。 2. 数据报文方式发送。 3. 不可靠。 4. 开销小。 5. 数据无序，接收到数据包顺序可能和发送的数据包顺序不一样。

33. 长连接和短连接

  1. 长连接是有连接的，例如 TCP、websocket，需要建立连接。
  2. 短连接不需要建立连接，例如 UDP、HTTP。
  3. 应用场景：需要服务端主动给客户端发消息的业务必须是长连接，其它都可以用短连接。

38. 菱形继承、如何处理

  1. 虚继承。

39. 智能指针的本质/实现原理

是利用了 C++ 析构函数自动调用的功能。C++ 对象被销毁时（delete、出栈）会自动调用析构函数，这是 C++ 编译器帮我们实现的。C 语言不但可以模拟 C++ 的面向对象思想：封装、继承、多态，而且除了 C++ 析构功能外，都可以实现。

智能指针内部维护了一个引用计数器，当引用计数器值为 0 时，销毁被指向的对象。

40. new和malloc的区别，new的对象可以用free进行释放并且成功吗，new的对象释放空间一定要调用析构函数吗

free 时可以释放空间，但是不能调用析构函数。如果是 free 方式释放的空间就不能调用析构函数。

41. 内存泄漏排查

原因： 1. 用 malloc 或 new 申请的空间没有 free/delete。 2. shared_ptr 循环引用。 3. 容器里不再使用的数据没有及时释放。 4. 打开的第三方库某个功能没有及时关闭。 5. 申请的内存超出系统限制。

排查与避免： 1. malloc/free、new/delete 配对使用，或者使用智能指针（如 C++ 的 unique_ptr、shared_ptr）自动管理生命周期。 2. 避免循环引用（尤其智能指针场景）。 3. 容器使用后及时清空，避免残留。 4. 及时释放资源句柄（文件、网络连接等）。 5. 用 RAII 模式封装资源，利用栈对象自动析构。 6. 定期用工具检测（Valgrind、Clang LeakSanitizer 等）。 7. 编码时明确内存所有权，避免野指针。

42. 程序的内存分配

静态分配内存：代码段，存放代码；数据段，全局变量和静态变量。 动态内存分配：堆，开发者维护的内存区域，手动申请和释放；栈，操作系统维护的，主要用于函数调用，硬件层次上支持。

43. 栈溢出的原因及检测和预防方法

原因：递归调用过深，函数嵌套层级过多，局部变量占用内存过大（如大数组），栈分配内存不足（系统或程序配置限制），缓冲区溢出（写入数据超出栈缓冲区范围）。

检测方法： - 静态分析：用代码检查工具（如 Clang Static Analyzer）扫描潜在风险。 - 动态调试：调试器（GDB）观察栈指针变化，设置栈溢出断点。 - 工具监测：使用 Valgrind（Memcheck）、AddressSanitizer 检测内存越界。 - 日志监控：记录函数调用栈深度，超过阈值报警。

预防方法： - 控制递归/嵌套深度，增加终止条件检查。 - 避免大尺寸局部变量，改用堆内存（动态分配）。 - 增大栈内存上限（如编译时调整栈大小参数）。 - 采用安全函数（如 strncpy 替代 strcpy）防止缓冲区溢出。 - 使用栈保护机制（如 GCC 的 -fstack-protector 编译选项）。

44. static和const的用法

static： 1. 全局 static 变量：存储在静态区；全局 static 变量只在本源文件（cpp、c、cc）可见；static 变量有默认值。 2. 函数内 static 变量：存储在静态区；只在当前函数内可见；有默认值；生命周期与程序一样长；不管函数调用多少次，只在第一次调用时初始化一次（显式初始化 static int count = 0;；默认初始化：static int count，值也为 0）。 3. 在类中，成员变量可以为 static，这个 static 属于类的，不属于对象（成员变量属于对象），该类的所有对象共享类的 static 变量。初始化方面，在类的外面显式初始化 int CTest::count = 0;。对比成员变量，类的 static 变量不需要实例化一个对象就可以使用。 4. static 函数：只能在本源文件中可见，不要在头文件中定义 static 函数。 5. static 类的成员函数：这个 static 属于类的，不属于对象。不需要实例化就可以访问，static 函数不能访问非 static 成员变量，类的 static 函数没有 this 指针。

const： 1. const 变量：不可修改（只能读，不能写），只能初始化一次，编译期优化。 2. const 全局变量：整个工程都可见，不局限于本源文件。 3. 函数内 const 变量：本函数可见。 4. 函数参数 const：本函数可见。 5. 返回值。 6. const std::string&。 7. const int* a;。 8. 成员变量 const。 9. static const int a;。

45. 结构体字节对齐的规则及为什么要字节对齐

规则： - 基本类型：自身大小为对齐值（如 char = 1，int = 4）。 - 结构体：成员最大对齐值为整体对齐值。 - 成员排列：每个成员起始地址为自身对齐值的整数倍，不足则填充。 - 整体大小：为整体对齐值的整数倍，不足则填充。

原因： - 硬件限制：多数 CPU 仅能高效访问对齐地址的数据，未对齐可能报错。 - 性能优化：对齐访问减少 CPU 内存读取周期，提升效率。 - 方便内存管理，减少内存碎片化。

46. 构造函数为什么不能声明为虚函数

虚函数依赖虚表指针（vptr），而 vptr 在构造函数执行时才初始化。构造函数的作用是初始化对象，此时对象尚未完全创建，无法确定具体类型。声明虚构造函数无实际意义，无法通过多态在构造阶段动态绑定类型。

47. 迭代器失效的原因

  • 容器重新分配内存（如 vector 扩容），原迭代器指向旧内存。
  • 删除/插入元素导致容器内部结构变化（如 vector 删除元素后后续迭代器失效）。
  • 关联容器（map/set）删除元素时，指向该元素的迭代器失效，其他不受影响。
  • 交换容器内容后，原迭代器指向另一容器的对应元素（视为失效）。

48. 指针与引用的区别

  • 指针：变量，存储另一个变量的地址，可空（nullptr），自身有地址。
  • 引用：变量的别名，必须初始化且绑定对象，不可为空，无自己的地址。
  • 指针：需解引用（*）访问目标，可被重新赋值指向其他对象。
  • 引用：直接访问目标，一旦绑定无法更改指向。
  • 指针：可能存在野指针、空指针风险，需检查有效性。
  • 引用：无空引用，安全性更高，编译期保证绑定有效对象。
  • 指针：动态内存管理、实现多态、传递可选参数（可空）。
  • 引用：函数参数/返回值（避免拷贝）、运算符重载。

49. 智能指针

类型：自动管理动态内存，避免泄漏。 - unique_ptr：独占所有权，不可复制。 - shared_ptr：共享所有权，引用计数，为 0 时释放。 - weak_ptr：配合 shared_ptr，不增加计数，解决循环引用。

需包含 <memory> 头文件，通过 make_shared 等创建。

实现原理： - 内部封装原始指针，重载 * 和 -> 运算符，模拟指针行为。 - 析构函数中自动释放所管理的内存（调用 delete/delete[]）。 - shared_ptr 通过引用计数：拷贝时计数 +1，销毁时计数 -1，计数为 0 时释放内存。 - unique_ptr 通过禁止拷贝、仅允许移动，确保唯一所有权，析构时直接释放。

函数参数使用独占指针的问题：可以，但传参时必须转移所有权（用 std::move），因为 unique_ptr 不可复制。

问题：实参所有权被转移到形参，函数外原指针变为空，无法再使用。若函数仅需临时访问而非接管所有权，传递 unique_ptr 会导致不必要的所有权转移，不合理（应传原始指针或引用）。

50. 递归

函数自身调用自身，需终止条件，否则栈溢出。分两部分：递归（调用自身缩小问题）+ 基线（终止条件返回结果）。优点：逻辑简洁；缺点：可能效率低、栈溢出。

51. 信号和槽

Qt 的核心机制，实现对象间通信。信号：对象状态变化时发出的通知。槽：接收信号并处理的函数。通过 connect 关联，信号触发时自动调用槽函数。支持跨线程通信，无需知道对方细节。

52. 堆栈

栈：自动分配释放，存储局部变量、函数调用信息，速度快，空间小（MB 级），先进后出。 堆：手动分配释放（malloc/new，free/delete），存储动态数据，空间大（GB 级），无序，速度较慢。 栈溢出快（递归/大变量），堆泄漏难察觉（忘记释放）。

53. C++的基类中哪些不能够被继承、有哪些函数不因为访问属性而不能被继承（比如友元函数）

  1. 不能被继承的：构造函数、析构函数。
  2. 不因访问属性限制但无法继承的：友元函数（友元关系不继承）、静态成员（属于类本身，并非继承）。

54. 多线程

线程是一条执行路径，多个线程是多条执行路径。一个进程里可以有多个线程，多线程共享进程内的资源，但线程内的栈数据不是共享的。多线程运行时要注意死锁的情况。

55. 共享资源的如何实现同步

常用锁和条件变量来实现。同一时刻只能有一个线程拥有锁，线程会等待某个条件的成立直到条件成立后才继续执行。通常锁和条件变量配合使用，典型的如生产者消费者模式。

56. 死锁产生的条件，如何避免死锁

形成了循环等待的闭环。避免死锁：尽量使用高级的并发工具，比如生产者消费者模式；必须使用锁的情况配合 std::lock_guard 使用，自动释放锁。

62. define和const的区别

  2. 类型检查：#define 无类型检查，const 有严格类型检查。
  3. 内存：#define 不占内存（仅替换），const 变量占内存。
  4. 作用域：#define 需手动 #undef 终止，const 受作用域限制。
  5. 调试：#define 无法被调试器识别，const 可以。

64. C/C++有什么区别

C 和 C++ 都是广泛使用的编程语言，它们在编程社区中有着重要的地位。两者的区别主要体现在以下几个方面：

  • 面向对象的特性：C++ 是面向对象的编程语言，它支持类和对象的概念，包括封装、继承和多态等特性。而 C 是一种过程式编程语言，不具备这些面向对象的特性。
  • 内存管理：C++ 提供了更多的内存管理功能，如 new 和 delete 操作符，允许程序员动态分配和释放内存。C 语言则主要依赖 malloc 和 free 函数进行内存的分配和释放。
  • 标准库和 API：C++ 拥有一个更为丰富和强大的标准库，包括了对字符串、文件流、异常处理等的支持。C 语言的标准库则相对简单，提供的函数数量和种类较少。
  • 类型安全：C++ 提供了更强的类型检查，有助于减少程序中的类型错误。C 语言的类型检查较为宽松，这可能导致潜在的类型转换错误。
  • 泛型编程：C++ 支持模板，这是一种泛型编程的工具，允许程序员编写可适用于多种数据类型的函数和类。C 语言不支持模板。
  • 异常处理：C++ 提供了异常处理机制，可以更有效地处理运行时错误。C 语言没有内置的异常处理机制，通常依赖于函数返回值来指示错误。
  • 语法和结构：C++ 的语法比 C 语言更复杂，包含了更多的关键字和构造。C 语言的语法相对简洁，学习起来可能更容易一些。
  • 性能：由于 C++ 提供了更多的抽象机制，如模板和异常处理，可能会导致编译后的代码比 C 语言的代码有轻微的性能损失。但是，这种差异在现代编译器和优化技术的帮助下已经大幅减少。
  • 应用领域：C 语言由于其接近硬件的特性，常用于系统编程、嵌入式开发等领域。C++ 则因其面向对象的特性，广泛应用于软件工程、游戏开发、高性能计算等领域。

总的来说，C++ 是在 C 语言的基础上发展起来的，增加了面向对象、泛型编程等特性，提供了更丰富的语言功能和更强的表达能力。但 C 语言以其简洁和高效的特点，在某些需要直接与硬件交互的领域仍然有着不可替代的地位。

65. 进程间的通讯

  • 管道（Pipe）：管道是一种半双工的通信方式，数据只能单向流动，且只能在具有亲缘关系的进程间使用。实现方式：在 Unix 系统中，可以使用 pipe() 系统调用创建管道；在 Windows 系统中，可以使用 CreatePipe() 函数创建管道。
  • 命名管道（NamedPipe）：命名管道也是半双工的通信方式，但它允许无亲缘关系进程间的通信。实现方式：在 Unix 系统中，可以使用 mkfifo() 系统调用创建命名管道；在 Windows 系统中，可以使用 CreateNamedPipe() 函数创建命名管道。
  • 信号（Signal）：信号是一种异步通信方式，用来通知接收进程某个事件已经发生。实现方式：在 Unix 系统中，可以使用 kill() 函数发送信号；在 Windows 系统中，可以使用 SendMessage() 或 PostMessage() 函数发送消息。
  • 消息队列（MessageQueue）：消息队列是一种消息的链表，存放在内核中并由消息队列标识符标识。实现方式：在 Unix 系统中，可以使用 msgget()、msgsnd() 和 msgrcv() 函数操作消息队列；在 Windows 系统中，可以使用 CreateFileMapping() 和 MapViewOfFile() 函数创建共享内存，然后通过读写共享内存实现进程间通信。
  • 信号量（Semaphore）：信号量是一个计数器，可以用来控制多个进程对共享资源的访问。实现方式：在 Unix 系统中，可以使用 semget()、semop() 等函数操作信号量；在 Windows 系统中，可以使用 CreateSemaphore() 函数创建信号量。
  • 共享内存（SharedMemory）：共享内存是最快的 IPC 方式，它允许多个进程共享一个内存区域，进程之间通过读写该内存区域来实现通信。实现方式：在 Unix 系统中，可以使用 shmget()、shmat() 等函数操作共享内存；在 Windows 系统中，可以使用 CreateFileMapping() 和 MapViewOfFile() 函数创建共享内存。
  • 套接字（Socket）：套接字是一种网络通信的进程间通信机制，支持不同主机之间的进程通信。实现方式：在 Unix 和 Windows 系统中，都可以使用 socket()、bind()、listen()、accept()、connect()、send() 和 recv() 等函数进行套接字编程。

66. 多进程和多线程的区别

  • 资源分配：多进程环境中，每个进程由操作系统分配独立的内存空间，拥有自己的资源和地址空间。而多线程环境下，所有线程共享所属进程的资源和地址空间。
  • 数据共享与同步：多进程中的每个进程有自己独立的数据，进程间需要通过 IPC（进程间通信）来进行数据交换，这增加了共享数据的复杂性。多线程由于共享进程的数据，因此数据共享相对简单，但需要复杂的同步机制来避免并发问题。
  • 通信机制：多进程间的通信通常涉及管道、信号、套接字等机制，而多线程可以直接通过共享内存进行交互，这使得线程间的通信效率更高。
  • 性能影响：创建新的进程通常比创建新线程消耗更多的系统资源，因为进程拥有独立的资源集。线程作为 CPU 调度的基本单位，其创建和上下文切换的开销小于进程，适合大量并发的场景。

67. 四种存储类型

  • auto：变量都是局部于某个程序范围内的。
  • register（寄存器型）：将所说明的变量放入 CPU 的寄存器存储空间中。
  • extern（外部参照引用型）：引用在其他文件中函数体外部说明的变量。
  • static（静态存储）：局部变量以固定地址存放。

68. 通讯协议（分类）

按通信方式分为： - 串行：一位一位地发送，线路简单成本低，灵活度高，可以远距离；速率较低。 - 并行：一次多位发送，速率高；成本高，抗干扰能力差。

按通信方向分为： - 单工：只能一个方向发。 - 全双工：可以同时收/发。 - 半双工：同一时刻只能收/发（共享一根线）。

数据同步方式分为： - 异步：靠起始位、停止位、校验接收位来保证数据传输的一致性。 - 同步：靠时钟来保证数据传输的一致性。

常见的几种通讯协议： - USART（全双工，同步+异步） - UART（全双工，异步） - I2C（半双工，同步） - SPI（全双工，同步） - CAN（半双工，异步） - USB

69. 构造函数和析构函数的作用

构造函数： - 初始化对象：构造函数用于构建对象时对成员变量进行初始化。 - 参数传递：可以通过构造函数的参数向对象传递初始化所需的数据。 - 重载函数：可以定义多个构造函数，以支持不同的初始化方式和参数组合。

析构函数： - 清理资源：在对象生命周期结束时进行清理工作，释放动态分配的内存，关闭文件等。 - 自动调用：当对象离开其作用域或被明确删除时，析构函数会被自动调用。

70. 什么是左值，右值，有什么东西可以既作左值又做右值

左值：可被取地址、能出现在赋值语句左侧的表达式，代表一个存储位置（如变量名、数组元素、解引用指针）。

右值：不可被取地址、只能出现在赋值语句右侧的表达式，代表临时值或字面量（如字面常量、表达式结果、临时对象）。

可既作左值又作右值的：变量（如 int a; a = 5; 中 a 是左值；int b = a; 中 a 是右值）、返回左值引用的函数调用、数组元素、结构体成员等。

区别： 1. 绑定对象：左值引用（&）只能绑定左值；右值引用（&&）只能绑定右值。 2. 用途：左值引用用于接收可寻址变量，避免拷贝；右值引用用于接收临时对象，支持移动语义和完美转发。

71. 内存对齐和结构体对齐的区别

内存对齐是通用规则（所有数据类型需地址为对齐值整数倍）；结构体字节对齐是其特例，除成员遵循内存对齐，还要求整体大小为最大成员对齐值的整数倍。

72. 模块

蜂鸣器： 1. 配置 GPIO：将蜂鸣器连接的引脚设为推挽输出。 2. 初始化引脚：调用 GPIO 初始化函数使配置生效。 3. 控制逻辑：输出高电平使蜂鸣器发声，低电平关闭。 4. 定时控制：用延时函数实现鸣叫时长控制。 5. 主循环：按需求调用蜂鸣器控制函数实现特定鸣叫模式。

DHT11（温度模块）： 四个引脚，实际使用 3 个：VCC、GND、DATA（数据线，需要串上拉电阻），第四个引脚无用。

先把 DATA 线拉低至少 18ms 发送信号，然后松开线（让它变回高电平），等 20-40us（等对方回应）。传感器收到信号后，会先拉低 DATA 线 80us（“我在！”），再拉高 80us（“可以说了”）。单片机检测到这两个高低电平，就知道可以开始读数据了。

传感器会发 40 个“位”的数据，每个位用“高电平持续时间”表示 0 或 1： 先拉低 50us（准备发一位），然后拉高：如果拉高时间 26-28us，就是“0”；如果 70us 左右，就是“1”。单片机一个个读，拼出 40 位数据。40 位数据分 5 部分，每部分 8 位： - 第 1-8 位：湿度整数（比如 30 → 30%） - 第 9-16 位：湿度小数（DHT11 这部分通常是 0） - 第 17-24 位：温度整数（比如 25 → 25°C） - 第 25-32 位：温度小数（DHT11 这部分也多为 0） - 第 33-40 位：校验位（前四部分加起来等于校验位，才说明数据有效）

DS18B20（温度传感器）： 三引脚：VCC：3.3V，GND：接地，DQ：数据线（需要上拉电阻保持高电平）。

初始化：单片机把 DQ 线拉低（输出低电平），持续至少 480us，松开 DQ 线（让它变回高电平），等 15~60us，如果传感器正常，会主动拉低 DQ 线 60~240us（相当于“回应”）。 单片机检测到这个低电平，就说明初始化成功。

重新初始化一次，还是发“跳过 ROM”命令（0xCC）。 发“读暂存器”命令（0xBE）：传感器会把测好的温度存在暂存器里，现在让它发出来。读取 2 个字节数据：第一个是温度低 8 位，第二个是高 8 位。 计算实际温度：把两个字节拼成 16 位数字，乘以 0.0625（因为 12 位精度下，最小单位是 1/16°C）。

W25Q64（Flash）： 1. 硬件连接：SPI 引脚（SCK 接 SPI_SCK，MOSI 接 SPI_MOSI，MISO 接 SPI_MISO，CS 接 GPIO），VCC 接 3.3V，GND 共地。 2. 配置 SPI：初始化 SPI 外设（主机模式，时钟极性/相位按器件要求，分频系数），配置 CS 引脚为推挽输出。 3. 基础指令： - 读 ID：发送 0x9F 指令，获取厂商/设备 ID 验证通信。 - 写使能：发送 0x06 指令，允许后续擦除/编程操作。 4. 数据操作： - 页编程：发送 0x02 指令 + 地址 + 数据（单次最多 256 字节）。 - 扇区擦除：发送 0x20 指令 + 地址（4KB）。 - 读取数据：发送 0x03 指令 + 地址，接收返回数据。 5. 功能函数：实现初始化、读写、擦除、状态查询函数。 6. 主循环：按需求调用擦除-写-读流程操作数据（注意擦除后才能写入）。

DS1302（时钟模块）： 就 8 个引脚，核心接 4 根线就行（以 STM32 为例）： - VCC1：主电源，接 3.3V（单片机供电） - VCC2：备用电池，接 CR2032 正极（掉电时供电，保持时钟运行） - GND：接地（和单片机、电池负极连一起） - SCLK：时钟线，接单片机任意 GPIO（比如 PB0，通信时提供时钟） - I/O：数据线，接任意 GPIO（比如 PB1，用来传数据） - RST：复位/使能线，接任意 GPIO（比如 PB2，拉高时才能通信）

核心是通过“三线通信”（SCLK、I/O、RST）给芯片发命令，读写时间数据。

  1. 初始化（准备工作） 先把 RST 线拉高（告诉芯片“要通信了”），SCLK 线拉低（时钟起始状态）。 芯片默认用 BCD 码存时间（比如“12 点”存成 0x12，“25 分”存成 0x25），读写时要注意格式转换。

  2. 写时间（设置当前时间） 比如要设成 2024 年 5 月 18 日 15 点 30 分 20 秒： 先给芯片发“写命令”（比如写秒的命令是 0x80，写分是 0x82，每个时间单位对应一个地址）。 再发对应的数据（秒 20 → 0x20，分 30 → 0x30，时 15 → 0x15，日期 18 → 0x18，月 5 → 0x05，年 24 → 0x24）。 注意：小时格式可以设 12 小时制或 24 小时制（通过小时数据的第 7 位控制）。

  3. 读时间（获取当前时间） 发“读命令”（比写命令地址大 1，比如读秒是 0x81，读分是 0x83）。 芯片会通过 I/O 线返回 BCD 码数据，比如读到 0x15 就是 15 时，0x30 就是 30 分。把 BCD 码转成十进制（比如 0x15 → 15，0x24 → 24），就能直接用了。

MQ-2（烟雾传感器）： 有 4 个引脚：VCC 接 5V，GND 接单片机地，AO 模拟输出（输出 0-5V 电压，浓度越高电压越大），DO 数字输出（当浓度超过阈值时，输出低电平；反之高电平，阈值可通过模块上的电位器调节）。

通常接 AO 脚到单片机的 ADC 引脚（比如 STM32 的 PA0），这样能读到具体浓度值；DO 脚可以接 GPIO，做简单的报警开关。

核心是读 AO 脚的电压值，换算成烟雾浓度（或相对浓度）：

  1. 初始化 ADC 单片机配置对应的 ADC 通道（比如 PA0），让它能读取 0-3.3V（或 0-5V，看单片机 ADC 范围）的电压。 如果传感器输出 5V 而单片机 ADC 最大 3.3V，最好串个分压电阻（比如两个 10K 电阻分压，把 5V 降到 2.5V 再读）。

  2. 读模拟值 通过 ADC 读取 AO 脚的电压，比如读到的 ADC 值是 2048（假设 12 位 ADC，满量程 3.3V），对应的电压就是（2048/4096）*3.3V ≈ 1.65V。烟雾/气体浓度越高，AO 脚输出的电压越大（比如干净空气可能 1V，有烟雾时升到 3V）。

  3. 换算成浓度（可选） 可以简单做个对应关系：比如把 ADC 值分成几个等级（低、中、高），对应“正常”“轻微烟雾”“严重烟雾”。精确的话需要校准：在干净空气中读一个基准值，再在已知浓度下读值，建立公式（比如浓度 = K * ADC 值 + B）。

  4. 数字输出用法（简单报警） 转动传感器模块上的电位器，设置报警阈值（比如烟雾浓度超过某值时 DO 脚变低）。单片机读 DO 脚的高低电平：低电平就触发蜂鸣器报警，高电平则正常。

73. 四种通讯协议

USART： 异步模式（UART）：无需时钟线，通过预设的波特率同步数据（最常用）。同步模式：需要时钟线（SCK），发送方控制时钟，适用于高速通信。全双工。 异步模式最少只需 2 根线：TX：发送数据（Transmit），RX：接收数据（Receive）。 数据帧结构（异步模式）：起始位（1 位低电平）+ 数据位（5-9 位）+ 校验位（可选）+ 停止位（1-2 位高电平）。

I2C（集成电路间总线）： 同步通信（依赖 SCL 时钟），半双工（同一时间只能收或发）。仅需 2 线： - SDA（SerialData）：双向数据线。 - SCL（SerialClock）：时钟线（由主机控制）。 数据帧结构：起始信号（SCL 高电平时，SDA 从高到低跳变）。地址帧（7 位地址 + 1 位读写位）。数据帧（8 位数据，带应答位 ACK）。停止信号（SCL 高电平时，SDA 从低到高跳变）。

SPI（串行外设接口）： 同步通信（依赖 SCK），全双工（同时收发）。 物理线路：4 线（基础配置）： - SCK（SerialClock）：时钟线（主机提供）。 - MOSI（MasterOutSlaveIn）：主机发送，从机接收。 - MISO（MasterInSlaveOut）：从机发送，主机接收。 - SS/CS（SlaveSelect）：从机选择线（低电平有效，控制哪个从机通信）。 数据帧结构：无固定格式，通常按 8 位/16 位传输，高位在前或低位在前可配置。

CAN： 总线结构：多节点共享一条总线（通常为双绞线），支持 127 个节点。 信号表示：采用差分信号传输（CAN_H 和 CAN_L），抗干扰能力强，适合工业环境。 传输速率：最高 1Mbps（短距离，如 40 米内），速率降低时通信距离可延长（如 50kbps 时可达 1km）。 帧结构：CAN 协议定义了多种帧类型，最常用的是数据帧，结构如下：起始位 → 仲裁场（ID+RTR）→ 控制场 → 数据场（0-8 字节）→ CRC 场 → ACK 场 → 结束位。

74. FreeRTOS

它可以帮助开发者更高效地管理多任务，实现实时响应。STM32+FreeRTOS 的核心优势：

  1. 多任务管理：将复杂应用分解为多个独立任务，每个任务有自己的优先级，操作系统负责调度。
  2. 实时性：支持任务优先级抢占，高优先级任务可打断低优先级任务，确保关键操作及时响应。
  3. 资源管理：提供信号量、互斥锁、消息队列等机制，解决多任务间的同步与通信问题。
  4. 低资源占用：内核体积小（可低至几千字节），内存需求低，适合 STM32 等 MCU。

基本概念： - 任务（Task）：最小执行单元，由函数实现，拥有独立的栈空间和状态（就绪、运行、阻塞、挂起）。 - 任务调度器：根据任务优先级和状态，决定哪个任务获得 CPU 时间（FreeRTOS 默认使用抢占式调度）。 - 队列（Queue）：用于任务间数据传递（异步通信），支持 FIFO（先进先出）模式。 - 信号量（Semaphore）：用于同步或资源保护（如限制同时访问某个硬件的任务数量）。 - 互斥锁（Mutex）：特殊的信号量，解决优先级反转问题，保护共享资源。 - 任务通知（Task Notification）：轻量级的任务间通信方式，比信号量/队列更高效。

常用指令：

任务管理： - xTaskCreate()：创建任务 - vTaskDelete()：删除任务 - vTaskSuspend()：挂起任务 - vTaskResume()：恢复任务 - vTaskPrioritySet()：设置任务优先级

调度控制： - vTaskDelay()：任务延时 - vTaskDelayUntil()：周期性延时 - taskYIELD()：任务主动出让 CPU

队列操作： - xQueueCreate()：创建队列 - xQueueSend()/xQueueSendToBack()：发送数据到队列 - xQueueReceive()：从队列接收数据 - xQueuePeek()：查看队列数据不删除 - vQueueDelete()：删除队列

信号量/互斥锁： - vSemaphoreCreateBinary()：创建二值信号量 - xSemaphoreCreateCounting()：创建计数信号量

事件标志组： - xEventGroupCreate()：创建事件组 - xEventGroupSetBits()：设置事件位 - xEventGroupWaitBits()：等待事件位

内存管理： - pvPortMalloc()：动态分配内存 - vPortFree()：释放内存 - xPortGetFreeHeapSize()：获取剩余堆大小

系统控制： - vTaskStartScheduler()：启动调度器 - vTaskEndScheduler()：停止调度器 - xTaskGetTickCount()：获取系统滴答数

77. 多态/以及构造函数能否作为虚函数

它指的是同一个接口或方法在不同的对象中可以有不同的实现方式。

当类中声明了虚函数（用 virtual 关键字修饰的函数）时，编译器会为该类创建一个虚函数表：

每个包含虚函数的类的对象，会在其内存布局的起始位置（通常）增加一个隐藏的指针成员，即虚函数指针（vptr）。

当通过父类指针/引用调用虚函数时，从对象的 vptr 找到所属类的 vtable。在 vtable 中根据函数索引找到对应的函数地址。调用该地址指向的函数（父类或子类的实现）。

  1. 虚函数是通过编译器生成 vtable 来实现的，vtable 里保存了虚函数的地址。（可以关联多态的面试题回答）
  2. 构造函数的调用顺序是先调用基类构造函数，这时的基类函数还看不到派生类的类型，无法进行多态。在实现上，这时的 vtable 还没有初始化好，无法使用 vtable。

78. 智能指针

需要注意的是，unique_ptr 没有复制构造函数，不支持普通的拷贝和赋值操作。因为 unique_ptr 独享被管理对象指针所有权，当 p2、p3 失去 p 的所有权时会释放对应资源，此时会执行两次 delete p 的操作。

原理是使用引用计数实现对同一块内存的多个引用。在最后一个引用被释放时，指向的内存才释放，这也是和 unique_ptr 最大的区别。当对象的所有权需要共享（share）时，shared_ptr 可以进行赋值拷贝。

shared_ptr 使用引用计数，每一个 shared_ptr 的拷贝都指向相同的内存。每使用他一次，内部的引用计数加 1，每析构一次，内部的引用计数减 1，减为 0 时，删除所指向的堆内存。

79. unique_lock和lock_guard的区别

lock_guard 是简单的锁管理类，一旦构造就会锁定互斥量，直到析构时才会自动释放锁，期间不能手动解锁或重新锁定。

unique_lock 更加灵活，可以在构造后手动调用 lock() 锁定，unlock() 解锁，还能通过 owns_lock() 检查是否持有锁。（配合条件变量来使用）
