自定义 ls 命令项目开发学习笔记

一、软链接与硬链接

1.1 软链接（符号链接）

  • 本质等同于 Windows 快捷方式
  • 可正常读取指向的原文件内容
  • 源文件删除后软链接失效，命令行中以红色特殊样式标识
  • 可跨文件系统、可对目录创建

1.2 硬链接

  • 本质是原文件的别名，多个硬链接指向同一文件实体
  • 判断依据：inode（索引节点）编号一致
  • 核心优势：删除任意一个硬链接不会清除文件实体，可防止误删
  • 限制：仅支持同一分区内跨目录创建，不能跨分区（inode 按分区独立分配）
  • 不能对目录创建硬链接

二、系统 IO 实现链表持久化

2.1 保存链表到文件

关键要点

  • 打开失败返回当前函数，不调用 exit 终止整个程序
  • 先写 0 占位，遍历完成后用 lseek 回到开头更新总数
  • 用 while 循环遍历，可自动校验节点完整性

2.2 从文件载入链表

2.3 版本管理

  • Debug 版本：make build debug，保留调试打印，便于排查
  • Release 版本：移除调试代码，无冗余提示
  • 首次验证时关闭载入逻辑，避免新旧数据格式不匹配
  • 历史旧文件兼容：仅读取文件头标记的有效节点数，无需清空冗余数据

三、自定义 ls 命令项目概述

3.1 项目背景

  • 源自军工项目场景（直升机黑匣子数据传输），VxWorks 系统禁止使用系统内置命令
  • 需自主开发类 ls 命令，便于安全检查

3.2 功能需求

需求 说明
基础能力 支持单个/多个文件、目录路径，自动遍历目录内容
-d 参数 传入目录时仅展示目录自身属性
异常兼容 路径参数混用目录/普通文件，重复参数不影响
输出属性 类型、权限、硬链接数、用户名、组名、大小、时间、文件名

3.3 功能拆解

将复杂功能拆解为两项独立核心需求：

  1. 单文件属性解析：给定文件名，分解出 8 项属性
  2. 目录内容遍历：给定目录路径，识别目录下包含的内容

lstat 文件路径 获取链接文件自身属性，不跟随

选型：lstat 可覆盖所有场景，为首选函数。

六、权限解析（八进制转 RWX）

6.2 十进制转二进制（位运算法）

  • 右移 >>：将数值向右移动指定位数
  • 与 1 做与运算 & 1：提取最低位
  • 循环 9 次得到完整的 9 位二进制

6.3 二进制映射为 RWX 字符串

  • 分组：前 3 位=所有者，中 3 位=所属组，后 3 位=其他人
  • 通过 i % 3 实现分组索引映射

七、特殊权限（setuid / setgid / 粘滞位）

7.1 特殊权限位提取

7.2 三位特殊权限

位 权限 数值 有 x 时 无 x 时
第1位 setuid 4 s S
第2位 setgid 2 s S
第3位 粘滞位 1 t T

7.3 替换规则

  • 特殊权限位为真时，替换对应位置的执行位 x
  • 原位置有 x → 小写 s/t
  • 原位置无 x（是 -）→ 大写 S/T

7.4 完整权限示例

完整 mode 输出字符串 说明
4755 rwsr-xr-x setuid + 所有者有 x
6755 rwsr-sr-x setuid + setgid
1777 rwxrwxrwt 粘滞位（/tmp 典型）
7654 rw-r-sr-T 特殊权限混合

8.1 UID 转用户名（getpwuid）

passwd 结构体字段

字段 说明
pw_name 用户名
pw_passwd 加密密码（通常为 x）
pw_uid UID
pw_gid GID
pw_gecos 用户备注
pw_dir 家目录
pw_shell 默认 Shell

8.2 GID 转组名（getgrgid）

验证方法：可通过 /etc/group 文件、id 命令输出与程序返回值比对。

8.3 调试要点

  • 先直接 printf 输出 st_uid、st_gid 数值，用 ls -la 比对确认读取正确
  • ll 是系统自定义别名，脚本中需用原生 ls 命令
  • 编辑器制表符建议设为 8 个空格，避免对齐错乱

九、文件时间属性

9.1 三种时间

字段 含义
st_atime 最后访问时间
st_mtime 最后修改时间（ls 默认显示）
st_ctime 状态改变时间

注意区分访问时间与修改时间，调试时容易混淆。

9.2 时间戳转本地时间（localtime）

  • localtime 为线程安全函数
  • 自动完成格林尼治时间到东八区的转换

9.3 struct tm 字段与修正规则

字段 含义 修正规则
tm_year 年 需加 1900
tm_mon 月 需加 1（0-11）
tm_mday 日 直接使用（1-31）
tm_hour 时 直接使用（0-23）
tm_min 分 直接使用（0-59）
tm_sec 秒 直接使用（0-60）
tm_wday 星期 0=周日，1-6=周一至周六
tm_yday 年内第几天 0-365

十二、开发规范与学习要求

12.1 双版本开发机制

  • 正式版：移除所有中间调试输出，仅输出目标结果
  • DEBUG 版：保留全量中间过程输出，通过 -DDEBUG 宏控制
  • 开发过程保留全量中间代码，便于问题回溯
  • 出现问题时开启 DEBUG 宏，逐环节定位错误

12.2 学习要求

  • 课程内容前后关联度极高，无特殊情况不得缺席
  • 位运算需反复打磨，提升开发反应速度
  • 深入领会十进制转二进制的实现过程

12.3 后续教学规划

  • 本周六完成全部开发，封装为可直接调用的独立项目模块
  • 下周正式开展多进程、多线程、网络编程相关技术内容
