一、消息队列

1.1 消息队列概述

消息队列是 IPC（进程间通信）的第二种技术。与共享内存相比，消息队列的特点是：

  • 带有标识的消息：每条消息都有一个类型标识（mtype），接收方可以按标识筛选消息
  • 具有持续性：消息写入队列后，即使发送方退出，消息仍保留在队列中，接收方可随时读取
  • 有序性：消息按发送顺序排列在队列中，支持按标识检索

1.2 使用流程

与共享内存类似，消息队列也遵循 IPC 通用流程：

  1. ftok() 生成唯一的 key
  2. msgget() 创建或获取消息队列
  3. msgsnd() 发送消息
  4. msgrcv() 接收消息
  5. msgctl() 控制（删除等）

1.3 核心函数

ftok — 生成 key

  • pathname：合法路径（必须存在）
  • proj_id：用户自定义整数标识
  • 返回值：成功返回 key，失败返回 -1

msgget — 创建/获取消息队列

  • key：由 ftok 生成
  • msgflg：标志位，如 IPC_CREAT | 0666
  • 返回值：成功返回消息队列 ID（msgid），失败返回 -1

msgsnd — 发送消息

  • msqid：消息队列 ID
  • msgp：指向消息结构体的指针
  • msgsz：消息数据的大小（不包含 mtype）
  • msgflg：标志位，通常写 0（阻塞等待）
  • 返回值：成功返回 0，失败返回 -1

msgrcv — 接收消息

  • msqid：消息队列 ID
  • msgp：接收缓冲区
  • msgsz：最大接收数据大小
  • msgtyp：要接收的消息类型标识
    • 0：接收队列中第一条消息
    • > 0：接收指定类型的第一条消息
    • < 0：接收类型小于等于其绝对值的最小类型消息
  • msgflg：标志位，通常写 0
  • 返回值：成功返回实际接收的字节数，失败返回 -1

msgctl — 控制消息队列

  • 常用 cmd：IPC_RMID（删除消息队列）、IPC_STAT（获取状态）、IPC_SET（设置状态）

二、信号量开发模型

2.1 信号量概述

信号量（Semaphore），也叫信号灯，是一种用于实现进程/线程间同步与互斥的机制。

  • 信号量本质是一个表示资源状态或资源数量的整数（或整数数组）
  • 通过 P 操作（申请资源）和 V 操作（释放资源）来控制对共享资源的访问
  • 信号量本身不传递数据，需要配合共享内存等通信方式使用

2.2 两种信号量技术

技术 说明 特点
System V 信号量 传统 Unix 标准，ipcs 工具管理 编程繁琐，需要自定义联合体，功能强大
POSIX 信号量 现代通用操作系统接口标准 编程简洁，效率更高，像操作文件一样使用

System V 中的 “V” 是罗马数字 5，表示 Unix 内核第五次重大版本变更中被统一化的标准。军用系统等对安全性要求高的场景仍在使用较早的技术。

2.3 信号量同步模型

以两个进程（写进程和读进程）通过共享内存通信为例，使用两个元素的信号量：

信号量元素 含义 初始值
data（下标 0） 数据是否可用 0（初始无数据）
space（下标 1） 空间是否可用 1（初始有空间）

P 操作和 V 操作

  • P 操作（申请资源）：将信号量值减 1。如果值变为负数，进程阻塞等待。
  • V 操作（释放资源）：将信号量值加 1。如果有进程在等待，唤醒其中一个。

2.5 与条件变量的对比

机制 等待时行为 适用场景

三、System V 信号量实现进程同步

3.1 核心函数

semget — 获取信号量集

  • key：ftok 生成的 key
  • nsems：信号量集中的元素个数（如 2）
  • semflg：标志位，如 IPC_CREAT | 0666
  • 返回值：成功返回信号量集 ID（semid），失败返回 -1

semctl — 控制信号量

  • semid：信号量集 ID
  • semnum：操作哪个元素（下标）
  • cmd：操作命令
    • SETVAL：设置信号量的值（需要第四个参数）
    • GETVAL：获取信号量的值
    • IPC_RMID：删除信号量集
  • 第四个参数（可选）：union semun 联合体

semop — 执行 P/V 操作

  • semid：信号量集 ID
  • sops：操作数组（struct sembuf 结构体）
  • nsops：操作数量

四、POSIX 信号量

4.1 POSIX 信号量概述

POSIX 信号量是比 System V 更现代、更简洁的信号量实现。它的设计更符合现代编程风格，使用起来像操作文件一样简单。

POSIX 信号量分为两种： - 命名信号量：有一个名字，不同进程通过名字打开同一个信号量（sem_open） - 无名信号量：基于内存的信号量，用于线程间或共享内存中的进程间同步（sem_init）

4.2 核心函数

sem_open — 打开/创建命名信号量

  • name：信号量名字（如 /sem_data，必须以 / 开头）
  • oflag：标志位，如 O_CREAT（不存在则创建）
  • 可变参数：创建时需要传 mode（权限，如 0666）和 value（初始值）
  • 返回值：成功返回信号量指针（sem_t *），失败返回 SEM_FAILED

sem_init — 初始化无名信号量

  • sem：信号量变量地址
  • pshared：是否在进程间共享
    • 0：仅在当前进程的线程间共享
    • 1：在进程间共享（需放在共享内存中）
  • value：初始值
  • 返回值：成功返回 0，失败返回 -1

sem_wait — P 操作（等待/申请）

  • 将信号量值减 1，如果值为 0 则阻塞等待
  • 成功返回 0，失败返回 -1

sem_post — V 操作（释放/通知）

  • 将信号量值加 1，如果有进程在等待则唤醒
  • 成功返回 0，失败返回 -1

sem_getvalue — 获取信号量当前值

  • sval：输出参数，保存当前值
  • 成功返回 0，失败返回 -1

sem_close / sem_unlink — 关闭/删除命名信号量

4.5 POSIX 信号量使用注意事项

  1. 只初始化一次：多进程间共享的信号量只能由一个进程初始化，其他进程只打开不初始化
  2. 启动顺序：建议先启动读进程（或负责初始化的进程），再启动写进程
  3. 命名规范：命名信号量的名字必须以 / 开头，且只能包含一个 /
  4. 编译链接：某些系统版本需要显式链接线程库 -lpthread 或实时库 -lrt
  5. 清理资源：使用完毕后调用 sem_close 关闭，sem_unlink 删除命名信号量

4.6 System V vs POSIX 信号量对比

对比项 System V 信号量 POSIX 信号量
获取方式 semget 返回 ID sem_open 返回指针 / sem_init 初始化变量
初始化 semctl + 自定义联合体 semun sem_open 的 value 参数 / sem_init 的 value 参数
P/V 操作 semop + struct sembuf sem_wait / sem_post
编程复杂度 繁琐（需自定义联合体、封装函数） 简洁（直接调用函数）
进程间共享 天然支持（通过 key） 命名信号量天然支持；无名信号量需放共享内存
查看/删除 ipcs / ipcrm 无统一命令（需在文件系统中操作 /dev/shm）

五、多线程入门

5.1 线程概述

线程是操作系统进程内部调度 CPU 的基本单位。也就是说，CPU 实际上是以线程为单位进行调度的。

  • 默认情况下，一个进程只有一个线程（主线程，即 main 函数所在的线程）
  • 多线程可以在同一个进程内并发执行多个任务，共享进程的地址空间和资源
  • 创建线程的开销远小于创建进程

并发 vs 并行： - 并发（Concurrent）：多个线程在 CPU 上轮流执行（时间片轮转），宏观上同时进行 - 并行（Parallel）：多核 CPU 上多个线程真正同时执行

5.2 核心函数

pthread_create — 创建线程

  • thread：输出参数，保存新创建的线程 ID（pthread_t 类型）
  • attr：线程属性，通常传 NULL 使用默认属性
  • start_routine：线程例程函数指针，函数签名为 void *func(void *arg)
  • arg：传递给线程例程的参数
  • 返回值：成功返回 0，失败返回错误号（注意：不是 -1）

pthread_self — 获取当前线程 ID

pthread_exit — 线程退出

  • retval：线程退出时的返回值（指针），可被 pthread_join 获取
  • 重要：线程退出必须用 pthread_exit，不能用 exit！exit 会终止整个进程

pthread_join — 线程结合（等待线程退出）

  • thread：要等待的线程 ID
  • retval：输出参数，二级指针，用于接收线程的返回值
  • 功能：阻塞等待指定线程退出，并获取其返回值
  • 返回值：成功返回 0，失败返回错误号

“结合”（join）是线程领域的术语，指一个线程等待另一个线程退出并获取其状态。面试中常问”线程结合”或”线程等待”。

5.4 线程退出与返回值获取

关键问题：返回值的内存生命周期

线程通过 pthread_exit(retval) 返回一个指针，主线程通过 pthread_join(tid, &retval) 获取。但这里有一个关键问题：

当 pthread_join 返回时，子线程已经执行完毕，其栈空间已被回收。如果返回值指向子线程的局部变量，那么该内存已经无效，获取到的将是垃圾值。

四种返回值方案

方案 说明 优缺点
局部变量 int val = 100; pthread_exit(&val); 不可行：函数结束后栈空间被回收
全局变量 定义在函数外部 可行，但全局变量污染命名空间，多线程不安全
静态局部变量 static int val = 100; 可行，空间在全局区，函数结束后仍存在，无需手动回收
堆空间 int *val = malloc(sizeof(int)); 可行，灵活，但需要主线程手动 free，否则内存泄漏

方案一：静态局部变量（推荐）

静态局部变量初始化时必须用常量（如 0），不能用需要运行时计算的值。

5.6 二级指针的理解

pthread_join 的第二个参数是 void **retval（二级指针），这是 C 语言中常见的模式：

  • 函数需要输出一个指针类型的值
  • 传入指针的地址（二级指针），函数内部通过 *retval = ... 给外部变量赋值

面试中常问二级指针的使用场景：pthread_join 获取线程返回值就是典型例子。

六、面试考点汇总

6.1 消息队列

  1. 消息队列和共享内存的区别？
    • 消息队列：带类型标识，支持按类型筛选，有持续性，内核管理
    • 共享内存：直接映射，效率最高，需要同步机制，无持续性概念
  2. msgrcv 的 msgtyp 参数有什么用？
    • 0：取第一条消息

    • 0：取指定类型的第一条消息

    • <0：取类型 ≤ |msgtyp| 的最小类型消息
  3. 消息队列的缺点？
    • 无数据时接收方阻塞空耗 CPU；数据大小有限制

6.2 信号量

  1. 什么是信号量？P 操作和 V 操作？
    • 信号量是表示资源数量的整数，用于同步互斥
    • P 操作：减 1，为 0 则阻塞（申请资源）
    • V 操作：加 1，有等待则唤醒（释放资源）
  2. System V 和 POSIX 信号量的区别？
    • System V：semget/semctl/semop，需自定义 semun 联合体，编程繁琐
    • POSIX：sem_open/sem_wait/sem_post，编程简洁，像操作文件
  3. 信号量和条件变量的区别？
    • 信号量：有计数值，可用于进程间，等待时阻塞
    • 条件变量：必须配合互斥锁，等待时休眠不占 CPU，更高效
  4. 信号量为什么要初始化？
    • 不初始化时值是随机的，会导致 P/V 操作异常。data 初始 0，space 初始 1
  5. ipcs/ipcrm 命令的使用？
    • ipcs 查看 IPC 资源，ipcrm 删除；-s 信号量、-m 共享内存、-q 消息队列

6.3 多线程

  1. 进程和线程的区别？
    • 进程是资源分配单位，线程是 CPU 调度单位
    • 进程有独立地址空间，线程共享地址空间
    • 线程创建开销小，通信方便；进程更安全，一个崩溃不影响其他
  2. pthread_exit 和 exit 的区别？
    • pthread_exit：只退出当前线程，进程继续运行
    • exit：终止整个进程，所有线程都结束
  3. pthread_join 的作用？二级指针参数？
    • 阻塞等待指定线程退出，获取返回值
    • 第二个参数是 void **，用于输出线程返回的指针
  4. 线程返回值为什么不能用局部变量？
    • 线程函数结束后栈空间被回收，局部变量地址无效
    • 解决方案：全局变量、静态局部变量、堆空间（malloc）
  5. 如何给线程传递参数？
    • pthread_create 第四个参数传 void *，可传任意类型地址
    • 线程函数内部通过强制类型转换获取参数
  6. 并发和并行的区别？
    • 并发：宏观同时，微观轮流（时间片轮转）
    • 并行：真正同时执行（多核 CPU）
