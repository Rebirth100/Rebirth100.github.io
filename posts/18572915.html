四、程序与进程

4.1 核心概念区分

对比项 可执行程序 进程
本质 静态文件 动态执行实例
存储位置 硬盘/外存 内存
资源占用 磁盘空间 CPU 调度 + 内存
与 CPU 关系 无关联 被 CPU 调度执行
数量 一份文件可多次运行 每次运行生成一个独立进程
  • 程序：存储在硬盘上的可执行指令序列文件
  • 进程：程序的一次动态执行过程

4.2 进程加载流程

  • swap 缓冲区：硬盘与内存之间的缓冲区域
  • 页面存储技术：指令边运行边加载、暂存，保障 CPU 指令流持续供给
  • 虚拟寻址：每个进程拥有 4G 虚拟寻址空间，通过存储管理模块动态分配回收物理内存

4.3 调度器

核心作用

  • 管理系统内所有运行进程的状态、资源占用、进程 ID
  • 合理分配 CPU 资源，让用户感知多进程同时运行

调度方式

优先级 调度方式 说明
普通 时间片轮询 单次时间片 50ms，CPU 可执行数十万条指令
高 先进先出 可抢占普通进程，如系统关机进程

4.4 进程控制块 PCB

  • 存储进程所有运行状态信息
  • 负责进程寻址空间管理
  • 为进程分配、查找对应资源地址
  • 为调度器调度提供数据支撑

4.5 线程

  • 定义：CPU 可调度的最小执行单位
  • 关系：进程内部可包含多个线程
  • 类比：华罗庚统筹法——烧开水的同时做准备工作，提升效率
  • 多核 CPU：支持多线程并行执行

4.6 进程创建流程

  • 终端执行 ./app 启动进程的底层逻辑：终端程序调用 fork + exec 完成进程启动

五、进程状态

5.1 三类核心状态

状态 说明
运行态 正在 CPU 上执行指令
休眠态 等待资源（如 IO、锁），时间片耗尽也会进入
暂停/挂起态 被信号暂停，等待恢复信号

5.2 状态转换规则

  • 所有状态切换均由调度器统一控制
  • 进程无法直接从暂停态跳转至休眠态
  • 两类状态的互相切换必须经过调度器的统一调度判定

5.3 进程退出

退出触发条件

  • 执行完所有指令，正常结束
  • 收到退出信号（如终端 Ctrl+C）

退出流程

  1. 进程执行完指令前先做自定义清理工作
  2. 进入待销毁状态
  3. 父进程通过 wait 函数完成子进程资源回收
  4. 进程正式销毁

5.4 信号基础

  • 信号可实现进程暂停、退出等控制
  • Ctrl+C 本质是向进程发送退出信号
  • 后续多进程学习需覆盖：fork 创建、exec 装载、信号发送与处理

六、多进程入门 — fork

6.1 进程查看命令

命令 作用
pstree 树形展示所有运行进程
ps aux 查看进程列表明细
ps -auf 查看进程列表与父子关系
ps -AUX 查看所有进程详细信息

6.2 fork 函数

返回值规则

返回值 含义
-1 出错
0 子进程拿到的返回值
>0 父进程拿到的返回值（即子进程的 PID）

核心特性

  • fork 调用会生成一个完整复制父进程所有资源的新进程
  • 新进程从 fork 代码行的下一行开始执行
  • 父、子进程均会执行后续代码，对应语句会打印 2 次

6.3 获取进程 ID

6.4 基础示例

6.5 连续 fork 的进程数计算

规则：每一次 fork 都会触发当前所有存活进程各自衍生一个新进程。

fork 次数 总进程数
1 次 2 = 2¹
2 次 4 = 2²
3 次 8 = 2³
n 次 2ⁿ

打印语句的执行次数需结合代码行具体位置计算，不同逻辑下次数存在差异。

6.6 固定数量直属子进程实现

需求：仅生成父进程的 6 个直属子进程，禁止子进程再衍生孙代。

方案一：子进程 break 跳出循环

方案二：子进程生成后直接暂停

  • 子进程不再执行后续 fork 逻辑

两种打印主体
| 主体 | 效果 |
|———|———|
| 父进程统一打印 | 父进程获取所有子进程 PID，便于管理 |
| 子进程自行打印 | 子进程生成后自行上报自身 ID |

6.7 注意事项

  • 测试前清理上一次未退出的遗留进程，避免干扰测试
  • 子进程 break 后仍会执行循环外的代码，需注意逻辑隔离
  • 父进程获取子进程 PID 是管理子进程的必要前提
