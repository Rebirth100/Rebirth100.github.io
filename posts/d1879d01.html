一、IO 模型演进回顾

Linux 网络编程中，处理 IO 的模型经历了以下演进：

模型 特点 适用场景
阻塞 IO 调用 recv 时阻塞等待，不占 CPU 简单的单连接场景
非阻塞轮询 fcntl 设置非阻塞，循环 recv 检查 不推荐，CPU 空转
select 多路复用 单线程监听多个 FD，fd_set 管理 跨平台，连接数 < 1024
poll 多路复用 单线程监听多个 FD，pollfd 结构体管理 无 1024 限制，连接数中等
信号驱动 IO 数据到达时内核发 SIGIO 信号通知 UDP 等无连接协议，高并发
epoll（进阶） 事件驱动，回调机制，高性能 Linux 高并发服务器

多路复用的含义：在通道宽度有限的情况下，加一层”高架”，利用同一个通道让更多数据通过。但凡有空间能放数据就放，提高通道利用率。

二、UDP 多线程收发

2.1 UDP 多线程架构

UDP 是无连接协议，不需要提前建立通道。为了实现同时收发数据，使用多线程：

  • 接收线程：阻塞调用 recvfrom 等待数据到达
  • 发送线程：处理业务逻辑，调用 sendto 发送数据

2.2 多网卡场景

客户端向服务器的多个 IP 地址发送数据，服务器绑定 0.0.0.0 后可以从所有接口收到数据。

2.3 recvfrom 获取发送方地址

recvfrom 的后两个参数用于获取发送方的地址信息：

  • client_addr：输出参数，保存发送方的 IP 和端口
  • client_len：输入输出参数，地址结构体长度

注意：recvfrom 的最后一个参数是指针（socklen_t *），不是值。传错会导致代码无法正常运行。

三、信号驱动 IO

3.1 信号驱动 IO 的概念

信号驱动 IO 是一种异步通知机制：当网卡收到数据时，CPU 产生中断，内核处理数据后知道数据属于哪个进程（通过端口号判断），然后向该进程发送 SIGIO 信号（29号信号）。进程注册信号处理函数，在信号处理函数中读取数据。

3.2 为什么 UDP 适合信号驱动

  • UDP 是无连接的，每个数据报独立，收到信号后直接读一次即可
  • TCP 是面向连接的，数据可能分片、需要重组，信号驱动处理复杂
  • 因此信号驱动 IO 主要用于 UDP

3.4 信号驱动 vs 阻塞 IO

对比项 阻塞 IO 信号驱动 IO
等待方式 recvfrom 阻塞 pause 休眠，信号唤醒
CPU 占用 阻塞时不占 CPU 休眠时不占 CPU
数据处理 主线程中处理 信号处理函数中处理
适用协议 TCP/UDP 均可 主要用于 UDP
复杂度 简单 需要设置 fcntl、注册信号

信号驱动 IO 的优势：进程在等待数据时可以做其他事情，数据到达时通过信号异步通知。适合高并发 UDP 服务器。

四、Unix 本地域套接字

4.1 Unix 本地域概述

Unix 本地域套接字（Unix Domain Socket）是一种在同一台主机上进行进程间通信的机制。虽然使用的是套接字 API，但通信不经过网络协议栈，而是通过本地文件实现，效率更高。

特点： - 用于同一台主机上的进程间通信 - 通过套接字文件（socket file）实现通信 - 支持 TCP（流式 SOCK_STREAM）和 UDP（数据报 SOCK_DGRAM） - 比网络套接字效率高（不经过网络协议栈） - netstat -aln 可以查看 Unix 域套接字

严格来讲，网络远程通信也是一种进程间通信方式。Unix 本地域是特殊的进程间通信。

4.2 核心区别

对比项 网络套接字 Unix 本地域套接字
地址族 AF_INET (IPv4) AF_UNIX / AF_LOCAL
地址结构 sockaddr_in sockaddr_un
地址内容 IP地址 + 端口号 文件路径
通信范围 跨网络 同一主机
协议 TCP/UDP 同样支持流式/数据报

4.6 注意事项

  1. 套接字文件：Unix 本地域使用文件路径作为地址，通信时会在文件系统中创建一个套接字文件
  2. 文件已存在：绑定前如果文件已存在，bind 会失败，需要先 unlink 删除
  3. 客户端也需要绑定：UDP 客户端如果需要接收回复，也需要绑定自己的套接字文件

  5. 查看命令：netstat -aln 或 ss -lx 查看 Unix 域套接字

五、Wireshark 抓包与 TCP/UDP 包结构

5.1 Wireshark 简介

Wireshark 是一个开源的网络抓包工具，可以捕获网络接口上的所有数据包，并解析各层协议的内容。

使用方法： 1. 启动 Wireshark，选择要监听的网络接口（网卡） 2. 开始捕获，该网卡上的所有数据包都会被截获 3. 可以通过过滤器筛选特定协议（如 tcp、udp、http、ip.addr == x.x.x.x） 4. 点击数据包可以查看各层的详细内容

面试常问：在写网络程序的过程中，有没有测试过包的结构？有没有用抓包工具理解数据？

5.2 数据包的四层封装

一个 TCP 数据包在网络中传输时，经过四层封装：

各层说明：

层次 协议数据单元 关键地址 典型协议
链路层 帧（Frame） MAC 地址 以太网
网络层 包（Packet） IP 地址 IP、ICMP、ARP
传输层 段（Segment）/数据报 端口号 TCP、UDP
应用层 数据 - HTTP、FTP、DNS

5.3 TCP 三次握手抓包分析

TCP 建立连接的三次握手，通过 Wireshark 可以清晰看到：

步骤 方向 标志位 序号(SEQ) 确认号(ACK)
第一次 客户端→服务端 SYN SEQ=x -
第二次 服务端→客户端 SYN+ACK SEQ=y ACK=x+1
第三次 客户端→服务端 ACK SEQ=x+1 ACK=y+1

抓包中可以看到： - SYN 包的数据包大小为 0（只有头部，没有数据） - 窗口大小（Window）：如 65535，表示接收缓冲区大小 - 序号（Sequence Number）：初始序号，用于数据重组

5.4 TCP 头部结构

TCP 标志位：

标志 含义
SYN 建立连接
ACK 确认
FIN 关闭连接
RST 重置连接
PSH 推送数据
URG 紧急指针有效（带外数据）

5.5 UDP 头部结构

UDP 头部只有 8 字节，比 TCP 头部（20~60 字节）小很多，开销小。

六、TCP 可靠传输机制

6.1 TCP 如何保证可靠性

TCP 是面向连接的可靠传输协议，通过以下机制保证可靠性：

机制 说明
序列号 每个字节都有序号，接收方按序号重组数据
确认应答 接收方收到数据后发送 ACK 确认
超时重传 发送方超时未收到 ACK，重新发送数据
流量控制 滑动窗口机制，防止发送方发送过快
拥塞控制 慢启动、拥塞避免、快重传、快恢复
校验和 检测数据传输过程中是否出错
连接管理 三次握手建立连接，四次挥手断开连接

6.2 序列号与确认应答

  • 发送方给每个字节的数据分配一个序列号
  • 接收方收到数据后，回复 ACK = 期望收到的下一个字节的序号
  • 发送方收到 ACK 后，知道之前的数据已成功到达

6.3 超时重传

  • 发送方发送数据后启动定时器
  • 如果在超时时间内未收到 ACK，重新发送该数据
  • 超时时间根据网络状况动态调整（RTT 估算）

6.4 滑动窗口（流量控制）

  • 接收方在 ACK 中通知自己的接收窗口大小（Window）
  • 发送方发送的数据不能超过接收方的窗口大小
  • 窗口大小动态变化，实现流量控制

6.5 拥塞控制

TCP 通过拥塞控制避免网络拥塞： - 慢启动：连接建立后，拥塞窗口从 1 开始指数增长 - 拥塞避免：达到慢启动阈值后，拥塞窗口线性增长 - 快重传：收到 3 个重复 ACK 时立即重传，不等超时 - 快恢复：快重传后调整阈值，进入拥塞避免

七、带外数据（紧急数据）

7.1 带外数据的概念

带外数据（Out-of-Band Data，OOB），也叫紧急数据，是 TCP 提供的一种机制，允许发送方将某些数据标记为”紧急”，接收方可以优先处理这些数据，而不必按顺序等待前面的数据处理完。

TCP 头部中的紧急指针（Urgent Pointer）： - 当 URG 标志位为 1 时，紧急指针有效 - 紧急指针指向紧急数据的最后一个字节的下一个位置 - 接收方收到 URG 标志后，可以优先读取紧急数据

注意：实际上 TCP 的带外数据并不是真正的”带外”传输，紧急数据仍然在正常的数据流中传输，只是通过 URG 标志和紧急指针标记出来，让接收方可以优先读取。

7.2 发送带外数据

  • MSG_OOB 标志：表示发送带外数据
  • 一次只能发送 1 字节的带外数据

7.4 带外数据的用途

带外数据在实际应用中使用较少，典型用途： - 远程登录（Telnet）中发送中断信号 - 通知对方紧急事件 - 链路切换时发送紧急指令

课程中提到：当网络链路断开需要切换到备份链路时，TCP 通过紧急指令来通知对方进行链路切换。

八、广播通信

8.1 广播的概念

广播（Broadcast）是一种一对多的通信方式，发送方发送一个数据包，同一局域网内的所有主机都能收到。

广播的特点： - 仅支持 UDP，不支持 TCP - 仅在局域网内有效，路由器不会转发广播包 - 目标 IP 地址为广播地址（如 192.168.1.255）或 255.255.255.255

8.2 广播地址

地址类型 示例 说明
受限广播 255.255.255.255 本局域网内所有主机，路由器不转发
直接广播 192.168.1.255 192.168.1.0 网络内所有主机

ARP 协议就是通过广播实现的：发送 ARP 请求时，目标 MAC 地址为 FF:FF:FF:FF:FF:FF（广播地址），询问”谁拥有这个 IP 地址”。

九、互联网拓扑与 BGP 协议

9.1 互联网拓扑结构

互联网的拓扑结构是分层的：

城域网（MAN，Metropolitan Area Network）： - 覆盖一个城市范围 - 由电信运营商部署光纤和路由器 - 企业/学校不能随意拉光纤，必须使用运营商的基础设施

9.2 备份链路

为了保证网络可靠性，重要节点之间通常部署多条链路：

  • 正常通信时使用主链路
  • 主链路故障时（如光纤被挖断），快速切换到备份链路
  • 路由器需要快速计算并切换路径

实际场景：两个校区的实验室之间通信，需要走城域网。如果主链路的光纤被施工挖断，路由器需要快速切换到备份链路。

9.3 BGP 协议

BGP（Border Gateway Protocol，边界网关协议）是互联网上用于在自治系统（AS）之间交换路由信息的协议。

BGP 的特点： - 路径矢量路由协议 - 在 AS 之间交换可达性信息 - 有大约 15 种路径选择算法 - 可以计算多条备份路径，主链路故障时快速切换

课程中提到：BGP 协议厉害到在两个节点之间选一条链路有大约 15 种算法，光把那些名字记住都不容易。目的是保证可以快速算出几个备份路径放着，以防链路断了立马切过来。

9.4 ARP 协议

ARP（Address Resolution Protocol，地址解析协议）用于将 IP 地址解析为 MAC 地址。

ARP 工作过程： 1. 主机 A 要向主机 B 发送数据，知道 B 的 IP 但不知道 MAC 2. 主机 A 广播发送 ARP 请求：“谁拥有 IP x.x.x.x？请告诉我你的 MAC 地址” 3. 主机 B 收到广播后，单播回复 ARP 响应：“我拥有这个 IP，我的 MAC 是 xx:xx:xx:xx:xx:xx” 4. 主机 A 收到响应后，将 IP-MAC 映射存入 ARP 缓存

在 Wireshark 中可以看到 ARP 广播包，目标 MAC 为 FF:FF:FF:FF:FF:FF。

十、面试考点汇总

10.1 IO 模型

  1. Linux 中有哪些 IO 模型？
    • 阻塞 IO、非阻塞 IO、IO 多路复用（select/poll/epoll）、信号驱动 IO、异步 IO
  2. select、poll、epoll 的区别？
    • select：fd_set 位图，最大 1024 FD，每次需重置，跨平台
    • poll：pollfd 结构体数组，无最大限制，events/revents 分离
    • epoll：事件驱动，红黑树+就绪链表，高性能，Linux 特有
  3. 信号驱动 IO 的原理？
    • 数据到达时内核发 SIGIO 信号通知进程
    • 进程在信号处理函数中读取数据
    • 主要用于 UDP，需要设置 fcntl(O_ASYNC) 和 F_SETOWN
  4. 为什么 UDP 适合信号驱动 IO？
    • UDP 无连接，每个数据报独立，收到信号读一次即可
    • TCP 面向连接，数据可能分片重组，信号驱动处理复杂

10.2 Unix 本地域

  1. Unix 本地域套接字和网络套接字的区别？
    • 地址族：AF_UNIX vs AF_INET
    • 地址：文件路径 vs IP+端口
    • 范围：同一主机 vs 跨网络
    • 效率：本地域更高（不经过网络协议栈）
  2. Unix 本地域支持 TCP 和 UDP 吗？
    • 支持，SOCK_STREAM 对应流式（TCP-like），SOCK_DGRAM 对应数据报（UDP-like）

10.3 TCP/UDP 与抓包

  1. TCP 头部有哪些字段？
    • 源端口、目的端口、序号、确认号、数据偏移、标志位、窗口大小、校验和、紧急指针、选项
  2. TCP 如何保证可靠传输？
    • 序列号、确认应答、超时重传、流量控制（滑动窗口）、拥塞控制、校验和、连接管理
  3. UDP 头部有哪些字段？为什么 UDP 比 TCP 快？
    • 源端口、目的端口、长度、校验和，共 8 字节
    • UDP 无连接、无确认、无重传、无流量控制，开销小
  4. Wireshark 抓包能看到什么？
    • 各层协议头部（以太网/IP/TCP/UDP）
    • 三次握手、四次挥手过程
    • 数据包的源/目的地址、端口、标志位、数据内容

10.4 带外数据与广播

  1. 什么是带外数据？如何发送和接收？
    • 带外数据（紧急数据）通过 URG 标志和紧急指针标记
    • 发送：send(fd, data, 1, MSG_OOB)
    • 接收：recv(fd, buf, 1, MSG_OOB)，或通过 SIGURG 信号
  2. 广播通信的特点？如何发送广播？
    • 仅支持 UDP，仅在局域网内有效
    • 发送前必须设置 SO_BROADCAST 选项
    • 目标地址为广播地址（255.255.255.255 或网络广播地址）
  3. ARP 协议的作用？
    • 将 IP 地址解析为 MAC 地址
    • 通过广播请求、单播响应实现
