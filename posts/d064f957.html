Linux 系统 IO 与数据持久化学习笔记

一、标准 IO 与标准设备

1.1 三类标准设备

设备 标识 默认绑定 文件描述符
标准输入 stdin / STDIN 键盘 0
标准输出 stdout / STDOUT 显示器 1
标准错误 stderr / STDERR 显示器 2
  • 系统标识统一以 STD 作为前缀
  • 进程启动时内核自动打开这三个设备，无需手动调用

1.2 标准设备的文件映射

  • Linux 遵循”一切皆文件”，所有设备在 /dev 目录下
  • 标准设备对应文件以 ST 开头，均为链接文件，存在多层链路映射
  • /dev/stdin → /proc/self/fd/0 → 实际终端设备
  • /proc 目录存储当前所有运行进程信息，终端作为进程，其标准设备最终指向当前操作终端

1.3 stdout 与 stderr 的区别

对比项 stdout stderr
缓冲区 有缓冲（遇换行或满刷新） 无缓冲，直接输出
用途 正常程序输出 错误信息
重定向 1> 或 > 2>

错误提示优先用 stderr，避免缓冲区未刷新导致错误信息看不到。

二、文件描述符（File Descriptor）

2.1 核心概念

  • 文件描述符是无符号整数，是进程打开文件在内核管理链表中的索引
  • 进程启动后，内核为每个打开的文件生成链表节点，FD 即该节点的索引编号
  • 用户无需手动管理，由内核自动分配和回收

2.2 分配规则

  • 默认占用：0（标准输入）、1（标准输出）、2（标准错误）
  • 新打开文件的 FD 从 3 开始递增
  • 已关闭的 FD 会被后续打开操作优先复用
  • 单个进程的 FD 存在固定上限，持续打开不关闭会触发资源耗尽

2.3 FD 上限测试

测试方法：循环以只读模式打开同一文件且不关闭，直到失败

测试结果： - 当前环境：FD 范围 0~1023，共 1024 个 - 不同版本系统有差异：Ubuntu 18.04 默认上限可达 8192 个 - 可通过系统调用查询当前上限

三、系统调用 open / close

3.1 open 函数

参数说明

参数 说明
pathname 文件路径
flags 打开标志位，支持多个标志位或运算组合
mode 新建文件的权限（仅当 flags 包含 O_CREAT 时需要）

常用标志位

标志 含义
O_RDONLY 只读
O_WRONLY 只写
O_RDWR 读写
O_CREAT 文件不存在则创建（需指定 mode）
O_APPEND 追加模式
O_TRUNC 清空原有内容

标志位组合：用位或 | 组合，如 O_CREAT | O_WRONLY | O_TRUNC

返回值 - 成功：返回文件描述符（≥0） - 失败：返回 -1，同时设置全局错误号 errno

3.2 文件权限 mode

  • 以八进制数字指定，如 0644、0755
  • 权限位：所有者（3位）+ 所属组（3位）+ 其他人（3位）
  • 支持特殊权限：setuid、setgid、sticky bit（最高位）
  • 示例：01764 → sticky bit + rwxrw-r–

3.3 close 函数

  • 传入文件描述符，释放内核资源
  • 头文件：unistd.h（Unix 标准库）
  • 操作完成后必须关闭，避免资源泄漏

3.4 错误处理

  • perror：打印自定义前缀 + 系统错误描述
  • errno：全局错误号，可通过 strerror(errno) 获取描述

四、系统调用 read / write

4.1 write 函数

参数 说明
fd 文件描述符
buf 待写数据的内存地址
count 要写入的字节数

返回值 - 成功：实际写入的字节数 - 失败：返回 -1

4.2 read 函数

参数 说明
fd 文件描述符
buf 接收数据的缓冲区地址
count 最多读取的字节数

返回值 - 成功：实际读取的字节数 - 读到文件末尾：返回 0 - 失败：返回 -1

系统 IO 没有内置的 EOF 判断接口，通过 read 返回值是否 > 0 判断是否读到有效数据。

4.3 标准 IO vs 系统 IO

对比项 标准 IO（fread/fwrite） 系统 IO（read/write）
操作对象 FILE* 文件指针 int 文件描述符
缓冲区 有缓冲区 无缓冲，直接系统调用
跨平台 C 标准，跨平台 POSIX 标准，Linux/Unix
效率 较高（缓冲减少系统调用） 二进制读写效率高
关闭 fclose close

五、随机读写 lseek

5.1 lseek 函数

参数 说明
fd 文件描述符
offset 偏移量（可正可负）
whence 基准位置

基准位置 whence

常量 含义
SEEK_SET 从文件开头偏移
SEEK_CUR 从当前位置偏移
SEEK_END 从文件末尾偏移

返回值：成功返回新的文件偏移量（相对于文件开头），失败返回 -1

六、链表数据持久化

6.1 设计目标

  • 程序退出后数据不丢失
  • 启动时从文件载入数据到链表
  • 链表模块与业务数据模块完全解耦

6.2 文件存储格式

  • 前 8 字节：数据条数 count（size_t）
  • 后续：每条业务数据固定长度

6.3 从文件载入链表（DBpass 函数）

6.4 模块解耦核心思想

  • 链表模块：只管节点的增删改查，不关心节点存什么数据
  • 业务模块：实现自己的初始化、拷贝、释放、打印函数
  • 适配方式：链表节点作为业务结构体的第一个成员
  • 函数指针：链表操作通过函数指针调用业务逻辑，不直接依赖业务类型

6.5 解耦后的复用场景

  • 学生信息管理系统
  • 后续网络编程：存储多个客户端连接信息
  • 任何需要链表的场景，只需实现业务配套函数

8.2 内核核心功能

8.3 Shell 与系统调用的关系

  • 绝大多数 Shell 命令本质是对内核系统调用的封装
  • 示例：
    • mkfifo 命令 → 同名系统调用
    • ll / ls -l → 封装 stat 系列系统调用获取文件属性

8.4 内核资源管理

  • 会话管理：用户登录后内核创建 session 结构体，链表串联所有在线用户
  • 文件管理：每个进程的打开文件通过链表管理，节点索引即文件描述符
