Linux 磁盘管理与 C 项目构建学习笔记

一、磁盘管理

1.1 磁盘管理完整流程

1.2 查看硬盘与分区

  • sd：串口硬盘（SATA）
  • sda：第一块串口硬盘，sdb：第二块
  • 建议切换 root 执行（sudo -i），避免权限不足

1.3 虚拟机添加新硬盘

  1. 右键虚拟机 → 设置 → 添加 → 硬盘
  2. 选择与原有硬盘相同类型（SCSI/SATA）
  3. 设置容量（如 80G），选单文件 VMDK
  4. 若 Linux 未识别新硬盘，重启虚拟机

1.4 分区表类型

类型 全称 主分区限制 特点
MBR 主引导记录 最多 4 个主分区 旧技术，存储在首个 512 字节扇区
GPT 全局唯一标识符分区表 无主分区数量限制 主流，支持大容量硬盘

MBR 分区结构 - 主分区 + 扩展分区总数 ≤ 4 - 扩展分区下可划分多个逻辑分区 - 第一个逻辑分区编号固定为 5（如 sda5） - 若 4 个主分区占满，剩余空间无法使用

1.5 fdisk 分区操作

交互界面常用命令

命令 作用
m 查看帮助菜单
g 创建 GPT 分区表
o 创建 MBR（DOS）分区表
n 新建分区
d 删除分区
p 打印分区表
l 列出分区类型编码
t 修改分区类型
w 保存并退出
q 不保存退出

常用分区类型编码 - 82：swap 交换分区 - 83：Linux 普通文件系统分区 - 05：扩展分区

操作前务必确认选中的硬盘路径，避免误操作系统盘。分区完成必须 w 保存。

1.6 格式化

swap 分区

普通分区

  • Linux 支持的文件系统：ext3、ext4、vfat 等
  • /etc/filesystems 记载系统支持的文件类型
  • vfat 可兼容识别 Windows 的 FAT32，但 Linux 文件系统结构无法被 Windows 识别
  • 扩展分区不能直接格式化，只能格式化其下的逻辑分区和主分区

  • 项目管理工具：自动管理多文件项目的编译流程

  • 自动构建依赖：依赖项不存在时，自动匹配规则生成

3.8 伪指令（.PHONY）

伪指令不生成对应文件，用于定义清理、安装等操作。

伪指令下的命令也必须以 Tab 开头，空格会报错。

3.9 项目交付规范

  • 核心代码不直接交付 .c 源码
  • 可交付 .o 目标文件 + 头文件，客户可编译链接但看不到实现
  • 或打包为静态库/动态库交付

四、静态库与动态库

4.1 库文件对比

平台 静态库 动态库
Linux libxxx.a libxxx.so
Windows xxx.lib xxx.dll

4.2 静态库制作

步骤

  • ar：归档工具
  • -r：替换/添加成员
  • -c：创建库（不提示）
  • -s：生成索引（ranlib 等效）

命名规范：必须以 lib 开头，.a 结尾，如 libmath.a

查看库内容

4.3 静态库使用

方式一：直接指定路径

方式二：-L 指定库目录，-l 指定库名（去掉 lib 和 .a）

  • -L.：当前目录搜索库
  • -lmath：链接 libmath.a

4.4 静态库特点

  • 编译时将库代码完整复制到可执行文件中
  • 运行时不依赖库文件
  • 可执行文件较大
  • 与调用路径强绑定
  • 交付客户时只需提供 .a 文件 + 头文件，隐藏核心实现

4.5 动态库（共享库）

制作

- -shared：生成共享库 - -fPIC：位置无关代码

使用

运行时需确保库在搜索路径中

或将库复制到 /usr/lib 或 /usr/local/lib

4.6 动态库特点

  • 运行时由操作系统按需加载
  • 多个程序共享同一份库代码，节省内存
  • 可执行文件较小
  • 需放置在系统 PATH / LD_LIBRARY_PATH 中
  • Windows 的 system32 目录有数千个 DLL，全量加载需 10G+ 内存，按需加载大幅降低占用
