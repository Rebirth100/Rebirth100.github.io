守护进程与进程间通信学习笔记

一、进程退出

1.1 两种退出方式

函数 头文件 行为
exit() stdlib.h 清理现场并退出（刷新缓冲区、调用注册函数）
_exit() unistd.h 不清理直接退出（缓冲区内容丢失）

现象验证

  • printf 输出到 stdout 是有缓冲区的，缓冲区满或遇到 \n 才刷新
  • _exit 直接退出，缓冲区内容不会刷到显示器
  • exit 会在退出前清理现场，刷新缓冲区

1.2 atexit 注册退出处理函数

  • 注册函数，进程正常退出时自动调用
  • 可注册多个，按注册顺序的逆序执行
  • 用于自定义清理逻辑（关闭文件、释放资源、写日志等）

1.3 安全退出方式

stderr 无缓冲，直接输出，调试提示优先用 stderr。

二、守护进程（Daemon）

2.1 概念

  • 操作系统启动时就一直运行，在后台默默等待被使用
  • 为完成某些特定系统服务而存在
  • 不随用户会话挂断而退出
  • 级别很高，只有操作系统关机时才退出

典型守护进程：sshd、systemd、crond 等

2.2 开发步骤（七步）

为什么要两次 fork？ - 第一次 fork + setsid：让子进程脱离原控制终端，成为新会话首领 - 第二次 fork + setpgrp：让子进程成为进程组长，级别提升到与系统服务同级 - 只有这样，原会话挂断或父进程退出才不会影响守护进程

2.4 syslog 系统日志

常用优先级

优先级 说明
LOG_EMERG 紧急，系统不可用
LOG_ALERT 需立即处理
LOG_CRIT 严重，会闪到所有控制台
LOG_ERR 错误
LOG_WARNING 警告
LOG_INFO 普通信息
LOG_DEBUG 调试信息
  • 日志默认写入 /var/log/syslog
  • LOG_CRIT 及以上会广播到所有登录终端
  • 系统会自动备份和压缩过大的日志文件

三、进程间通信概述

3.1 为什么需要通信

  • 进程之间默认是资源隔离的，相互看不见对方
  • 需要通过第三方共享资源实现数据交换和同步

3.2 通信技术分类

3.3 通信模式

模式 说明 示例
单工 数据只能单向流动 广播、收音机
半双工 可双向，但同一时刻只能一个方向 对讲机
全双工 可同时双向通信 电话

四、匿名管道

4.1 pipe 函数

  • 传入一个含 2 个元素的整型数组
  • 成功返回 0，失败返回 -1
  • pipefd[0]：读端
  • pipefd[1]：写端

4.2 核心特性

特性 说明
适用范围 仅近亲进程（fork 父子进程）
存储位置 内存中，无磁盘文件
原子性 不保证写入/读取的原子性
方向 单工，固定方向（需双向则开两个管道）
默认大小 128 字节（可通过 fcntl 修改）

五、有名管道 FIFO

5.1 mkfifo 函数

  • pathname：管道文件路径
  • mode：权限（如 0666）
  • 成功返回 0，失败返回 -1

命令行创建

特性 说明
适用范围 任意进程（无亲缘关系也可）
磁盘文件 有入口，但大小始终为 0 字节
实际通信 依托内存，数据不落盘
原子性 保证操作的原子性
方向 半双工，可双向（需错开时序）

六、信号

6.1 概念

  • 信号是一种软中断技术
  • 进程运行中，外部可发送信号，进程收到后暂停当前工作，执行信号处理函数，完成后回到原位置继续
  • 属于异步通信：发送方不关心对方是否收到、是否响应

6.2 信号发送方式

方式 说明
kill 命令 kill -信号编号 PID
kill() 函数 代码中发送
raise() 给自身发信号
键盘快捷键 Ctrl+C（SIGINT）、Ctrl+（SIGQUIT）

6.3 常用信号

编号 名称 默认行为 能否忽略
1 SIGHUP 终止 能
2 SIGINT 终止（Ctrl+C） 能
3 SIGQUIT 终止+core dump 能
9 SIGKILL 强制终止 不能
10 SIGUSR1 用户自定义 能
12 SIGUSR2 用户自定义 能
14 SIGALRM 终止（闹钟） 能
15 SIGTERM 终止（默认） 能
17 SIGCHLD 子进程退出通知 能
19 SIGSTOP 暂停 不能

SIGKILL(9) 和 SIGSTOP(19) 不能被捕获、阻塞或忽略。

6.4 signal 函数

  • sig：信号编号
  • handler：处理方式
    • SIG_IGN：忽略该信号
    • SIG_DFL：默认行为
    • 自定义函数指针

6.5 kill 函数

  • 给指定进程发送信号
  • pid > 0：发给指定进程
  • pid == 0：发给同组所有进程
  • pid == -1：发给所有有权限的进程

七、IPC 技术（System V）

7.1 通用前提：ftok

所有 IPC 技术都需要先通过 ftok 获取一个 key（标识）。

  • pathname：一个存在的文件路径
  • proj_id：项目编号（1~255）
  • 返回 key 值，用于后续 shmget/msgget/semget

两个进程用相同的 pathname 和 proj_id 就能得到相同的 key，从而找到同一个 IPC 资源。

7.2 共享内存

原理：让两个无关进程映射同一片物理内存，通过指针直接读写。

核心函数

函数 作用
shmget(key, size, flag) 创建/获取共享内存
shmat(shmid, addr, flag) 映射到进程地址空间，返回指针
shmdt(addr) 分离共享内存
shmctl(shmid, cmd, buf) 控制（删除等）

特点 - 速度最快（直接内存操作） - 不自带同步机制，需配合信号量 - 多个进程映射同一片物理内存

7.3 消息队列

原理：带标识的消息链表，进程按标识收发消息。

消息结构（必须）

核心函数

函数 作用
msgget(key, flag) 创建/获取消息队列
msgsnd(msqid, buf, size, flag) 发送消息
msgrcv(msqid, buf, size, type, flag) 接收指定类型消息
msgctl(msqid, cmd, buf) 控制（删除等）

特点 - 自带消息标识，可按类型过滤 - 内核维护队列，有顺序保障 - 适合结构化数据交换

7.4 信号量

原理：表示资源数量/状态的整数数组，实现进程间同步。

核心函数

函数 作用
semget(key, nsems, flag) 创建/获取信号量集
semop(semid, sops, nsops) P/V 操作
semctl(semid, semnum, cmd, ...) 控制（初始化/删除）

P 操作（申请资源）：信号量值 -1，若为 0 则阻塞等待 V 操作（释放资源）：信号量值 +1，唤醒等待进程

生产者-消费者同步模型

特点 - 自带同步机制 - 不传输数据，只控制时序 - 面试高频考点：P/V 操作
