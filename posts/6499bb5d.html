一、信号基础与发送处理

1.1 信号的概念

信号是一种异步事件通信模式。当进程运行过程中收到外部信号时，会暂时进入信号处理流程，处理完毕后回到原流程继续执行。

信号处理从两个层面理解：

  • 内核层面：内核负责信号的传递和管理
  • 用户层面：用户进程注册信号处理函数，定义收到信号后的行为

1.2 信号的分类

使用 kill -l 命令可查看系统支持的所有信号（共 62 个，缺少 32 和 33 号）。

类别 编号范围 别名 特点
非实时信号 1 ~ 31 不可靠信号 不保证执行顺序，不保证一定执行
实时信号 34 ~ 64 可靠信号 保证执行，保证按发送顺序处理

1.3 信号的四种处理方式

处理方式 说明
默认行为 大部分信号的默认行为是终止进程
忽略 收到信号后不做任何处理（SIG_IGN）
自定义处理函数 注册信号处理函数，收到信号后执行该函数
暂时阻塞 延迟处理，不是不处理，而是暂时不处理

注意：并非所有信号都能被忽略或捕获。

  • 9 号信号（SIGKILL）：不能被忽略、捕获或阻塞，是系统管理员强制终止进程的手段
  • 19 号信号（SIGSTOP）：暂停进程，不能被忽略
  • 18 号信号（SIGCONT）：让暂停的进程继续运行

1.4 信号的发送方式

方式一：kill 命令

示例：kill -9 1234 向 PID 为 1234 的进程发送 9 号信号。

方式二：kill 函数

方式三：用户操作触发

操作 触发信号 效果
Ctrl+C SIGINT(2) 中断进程
Ctrl+Z SIGTSTP(20) 暂停进程（停止交互）
改变窗口大小 SIGWINCH(28) 通知窗口大小变化

二、信号阻塞与延迟处理

2.1 信号集的概念

信号集（sigset_t）本质是一个无符号长整型，每一位代表一个信号。通过信号集可以统一管理一组信号，实现信号的阻塞与解除阻塞。

默认情况下，信号由进程直接管理；搭配信号集后，信号的管理主体切换为信号集。

2.2 信号集操作函数

2.3 sigprocmask 设置信号掩码

参数 how 的取值：

取值 含义
SIG_BLOCK 将 set 中的信号添加到当前阻塞集合（阻塞新信号）
SIG_UNBLOCK 将 set 中的信号从当前阻塞集合中移除（解除阻塞）
SIG_SETMASK 将当前阻塞集合设置为 set
  • set：要操作的信号集
  • oldset：保存原来的信号集状态（可为 NULL）

2.4 阻塞延迟处理示例

原理说明：阻塞期间，信号实际上已经被进程感知到（进入挂起队列），只是暂时不处理。解除阻塞后，挂起的信号会被处理。

2.5 实时信号与非实时信号的实验对比

通过信号阻塞后统一发送、再解除阻塞的方式，可以观察两类信号的差异：

  • 非实时信号（1~31）：解除阻塞后，不保证执行顺序，相同信号可能只执行一次（不排队）
  • 实时信号（34~64）：解除阻塞后，保证按发送顺序执行，每个信号都会被处理（排队）

2.6 进程结构体中的信号处理

在 Linux 内核的 task_struct 进程结构体中，包含信号处理相关字段：

  • 阻塞信号集（blocked）：当前被阻塞的信号
  • 挂起信号集（pending）：已收到但尚未处理的信号
  • 挂起信号有对应的挂起队列

3.1 简单版本 vs 复杂版本

3.6 双向通信思路

接收方通过 info->si_pid 可以获取发送方的 PID，因此可以反过来向发送方发送信号，实现双向通信：

  • A 给 B 发信号，携带数据
  • B 收到后，通过 info->si_pid 知道 A 的 PID
  • B 调用 sigqueue(info->si_pid, sig, value) 给 A 回发信号

注意：8 号信号（SIGFPE，浮点异常）有特殊含义，使用时需注意，可能触发默认的致命错误行为。建议使用其他编号做自定义通信。

四、进程退出与等待

4.1 exec 函数组

exec 函数组用于在当前进程中装载并执行另一个程序。调用成功后，当前进程的代码段、数据段被替换，从新程序的 main 开始执行，不会返回到原调用点。

4.3 wait 函数：等待子进程退出

  • 功能：阻塞等待任意一个子进程退出
  • status：输出参数，保存子进程的退出状态
  • 返回值：退出的子进程 PID，失败返回 -1

如果有多个子进程，wait() 会在任意一个退出时返回。需要等待所有子进程时，需要循环调用。

4.4 waitpid 函数：等待指定进程

参数说明：

  • pid：要等待的子进程 PID
    • > 0：等待指定 PID 的子进程
    • -1：等待任意子进程（等同于 wait）
    • 0：等待与调用进程同组的任意子进程
  • status：输出参数，保存退出状态
  • options：选项
    • 0：阻塞等待，直到指定进程退出
    • WNOHANG：非阻塞，如果没有子进程退出立即返回 0

4.5 进程退出状态的解析

重要特性：退出状态只占 1 个字节

进程退出时的返回值（return 或 exit() 的参数）虽然是 int 类型，但系统只使用低 8 位（1 个字节）存储实际退出值。

因此：

  • 合法范围：0 ~ 255
  • 直接读取 status 的值会是 256 的倍数（因为退出值存在高位字节）
  • 必须使用系统提供的宏来解析

值 含义

早年有些程序员喜欢用 return -1 表示错误，这是不好的习惯。应该使用 0 表示正常，1~255 表示不同类型的错误。

五、共享内存

5.1 共享内存概述

共享内存是最高效的进程间通信方式之一。它将同一块物理内存映射到多个进程的虚拟地址空间，进程可以直接读写这块内存，无需内核中转或数据拷贝。

三种 IPC 技术（共享内存、消息队列、信号量）都遵循相同的使用流程：

  1. 调用 ftok() 生成唯一的 key
  2. 通过 key 创建/获取 IPC 资源
  3. 映射/连接到进程
  4. 读写操作
  5. 分离/删除资源

5.2 ftok：生成 IPC key

参数说明：

  • pathname：一个合法的文件或目录路径（必须存在且可访问）
  • proj_id：用户自定义的整数 ID（通常取 1~255），用于在同一路径下区分不同的 IPC 资源

返回值：

  • 成功返回生成的 key（key_t 类型）
  • 失败返回 -1

关键点：两个进程要使用同一个共享内存，必须使用相同的 pathname 和 proj_id 调用 ftok()，这样才能生成相同的 key。

5.3 shmget：创建/获取共享内存

参数说明：

  • key：由 ftok() 生成的 key，或 IPC_PRIVATE（创建私有共享内存）
  • size：共享内存的大小（字节），如 1024
  • shmflg：标志位，通常为 IPC_CREAT | 权限，如 IPC_CREAT | 0666

返回值：

  • 成功返回共享内存 ID（shmid）
  • 失败返回 -1

与打开文件不同，shmget 的创建标志和权限用按位或写在同一个参数中。

5.4 shmat：映射共享内存到进程

参数说明：

  • shmid：共享内存 ID（由 shmget 返回）
  • shmaddr：指定映射到进程的哪个虚拟地址
    • 传 NULL：由操作系统自动选择合适的地址（推荐）
    • 传非 NULL：尝试映射到指定地址（不推荐，可能与现有空间冲突）
  • shmflg：标志位，通常传 0（可读可写），或 SHM_RDONLY（只读）

返回值：

  • 成功返回映射后的内存地址指针
  • 失败返回 (void *)-1

5.5 shmdt：分离共享内存

  • 功能：将共享内存从当前进程的地址空间分离
  • shmaddr：之前由 shmat 返回的地址
  • 成功返回 0，失败返回 -1

分离不等于删除！分离后共享内存仍然存在，其他进程仍可使用。

5.6 shmctl：控制共享内存

常用 cmd 取值：

命令 含义
IPC_STAT 获取共享内存的状态信息（存入 buf）
IPC_SET 设置共享内存的参数（从 buf 读取）
IPC_RMID 删除共享内存资源
SHM_LOCK 锁定共享内存（不被换出到交换区）
SHM_UNLOCK 解锁共享内存

删除共享内存后，已经映射的进程仍可继续使用，直到所有进程都分离后才真正释放。

5.7 进程虚拟地址空间

Linux 进程的虚拟地址空间为 4GB（32位系统）：

  • 前 640KB：PCB 进程控制块区域，程序员不可操作
  • 栈空间：从高地址向低地址增长
  • 堆空间：从低地址向高地址增长
  • 共享内存映射区：位于堆和栈之间

使用 shmat 时传 NULL，操作系统会在映射区中自动分配一块不冲突的地址。

六、面试考点汇总

6.1 信号相关

  1. 信号的处理方式有哪些？

    • 默认行为、忽略、自定义处理函数、暂时阻塞

  2. 哪些信号不能被捕获或忽略？

    • SIGKILL(9) 和 SIGSTOP(19)

  3. 实时信号和非实时信号的区别？

    • 非实时信号（1~31）：不保证执行顺序，不保证一定执行，不排队
    • 实时信号（34~64）：保证执行，保证按顺序执行，支持排队

  4. signal 和 sigaction 的区别？

    • signal：简单，只能注册单参数处理函数，不能获取携带数据
    • sigaction：功能强，支持三参数处理函数，可获取 siginfo_t 详细信息，支持 SA_SIGINFO 等标志

  5. sigqueue 和 kill 的区别？

    • kill：只能发送信号编号
    • sigqueue：可以发送信号并携带数据（sigval 联合体）

6.2 进程退出与等待

  1. 进程退出方式有哪些？

    • 正常退出：return、exit()、_exit()
    • 异常退出：被信号终止、abort()

  2. wait 和 waitpid 的区别？

    • wait：阻塞等待任意子进程
    • waitpid：可等待指定 PID 的子进程，支持非阻塞模式（WNOHANG）

  3. 如何正确获取子进程退出状态？

    • 不能直接读取 status，需要用 WIFEXITED 判断是否正常退出，再用 WEXITSTATUS 获取真实退出码
    • 退出状态只占 1 个字节，范围 0~255

  4. exec 函数组的作用和区别？

    • 替换当前进程映像，执行新程序，成功后不返回
    • l/v 区别：列表传参 vs 数组传参
    • 有无 p：是否从 PATH 搜索可执行文件

6.3 共享内存与 IPC

  1. 共享内存的使用流程？

    • ftok 生成 key → shmget 创建/获取 → shmat 映射 → 读写 → shmdt 分离 → shmctl 删除

  2. 共享内存为什么效率高？

    • 直接映射内核空间到用户进程，无需数据拷贝和内核中转

  3. Linux 下管理 IPC 资源的命令？

    • ipcs 查看、ipcrm 删除
    • 不能只知道 kill，还需要掌握 IPC 资源管理命令

  4. shmat 的第二个参数传 NULL 是什么意思？

    • 由操作系统自动选择映射地址，避免与进程现有地址空间冲突

  5. shmdt 和 shmctl(IPC_RMID) 的区别？

    • shmdt：分离，进程不再使用，但共享内存仍存在
    • shmctl(IPC_RMID)：删除共享内存资源，所有进程分离后真正释放
