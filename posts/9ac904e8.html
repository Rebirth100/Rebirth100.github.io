一、网络编程基础

1.1 TCP 与 UDP

网络应用程序开发中最常见的两种通信模式是 TCP 和 UDP。

对比项 TCP UDP
连接方式 面向连接（类比打电话） 无连接（类比发短信）
可靠性 可靠传输，保证数据完整有序 不可靠，不保证到达和顺序
传输前 需先建立连接（三次握手） 无需建立连接，直接发送
确认机制 有确认、重传、流量控制 无确认机制
适用场景 网页、邮件、文件下载(FTP) 直播、视频通话、DNS查询
速度 相对较慢（开销大） 快（开销小）

TCP 类比打电话： 先拨号 → 对方接听 → 确认连通 → 开始说话 → 通话结束挂断。

UDP 类比发短信： 编辑消息 → 直接发送 → 不关心对方是否在线、是否收到。

对数据质量有要求、需要可靠验证的操作用 TCP（如打开网页、下载邮件、FTP下载资料）；瞬间数据量大但可靠性要求不高的用 UDP（如视频直播）。

listen — 开始监听

  • sockfd：套接字描述符
  • backlog：等待连接队列的最大长度（如 5、10、128）
  • 返回值：成功返回 0，失败返回 -1

listen 只是将套接字变为被动监听模式，并不接受连接。

accept — 接受客户端连接

  • sockfd：监听套接字描述符
  • addr：输出参数，保存客户端地址信息（可为 NULL）
  • addrlen：输入输出参数，地址结构体长度（可为 NULL）
  • 返回值：成功返回新的套接字描述符（用于与该客户端通信），失败返回 -1

accept 是阻塞函数，没有客户端连接时会一直等待。返回的新套接字才是用于收发数据的套接字。

connect — 客户端连接服务端

  • sockfd：套接字描述符
  • addr：服务端地址
  • addrlen：地址长度
  • 返回值：成功返回 0，失败返回 -1

send / recv — 收发数据

  • sockfd：套接字描述符（accept 返回的客户端套接字）
  • buf：发送/接收缓冲区
  • len：数据长度
  • flags：标志，通常传 0
  • 返回值：send 返回实际发送的字节数；recv 返回实际接收的字节数（0 表示对方关闭连接，-1 表示错误）

三、TCP 服务器多线程

3.1 为什么需要多线程

基础 TCP 服务器一次只能处理一个客户端连接（accept 阻塞，recv 也阻塞）。要支持多个客户端同时连接和通信，需要将服务器改造为多线程模式。

多线程服务器架构： - 主线程：负责 accept 接受新连接 - 每个客户端连接：创建一个子线程专门负责与该客户端收发数据 - 客户端和服务端都需要多线程：既可以发数据，也可以同时收数据

六、面试考点汇总

6.1 TCP 基础

  1. TCP 和 UDP 的区别？
    • TCP：面向连接、可靠传输、有序、有流量控制和拥塞控制，类比打电话
    • UDP：无连接、不可靠、不保证顺序、开销小速度快，类比发短信
    • TCP 适用于网页、邮件、文件传输；UDP 适用于直播、视频通话、DNS
  2. TCP 三次握手和四次挥手？
    • 三次握手建立连接：SYN → SYN+ACK → ACK
    • 四次挥手断开连接：FIN → ACK → FIN → ACK
  3. TCP 服务端编程流程？
    • socket → bind → listen → accept → recv/send → close
  4. TCP 客户端编程流程？
    • socket → connect → send/recv → close
  5. accept 返回的套接字和监听套接字有什么区别？
    • 监听套接字：用于接受新连接，整个服务器只有一个
    • accept 返回的新套接字：用于与特定客户端通信，每个客户端连接一个
  6. 什么是字节序？为什么需要转换？
    • 网络字节序是大端，主机可能是小端
    • htons/htonl 主机转网络，ntohs/ntohl 网络转主机

6.2 多线程服务器

  1. 为什么 TCP 服务器需要多线程？
    • 单线程服务器一次只能处理一个客户端，accept 和 recv 都会阻塞
    • 多线程可以同时处理多个客户端连接，实现并发
  2. 为什么要为每个客户端 malloc 新空间？
    • while 循环中局部变量地址通常不变，多个线程会共享同一地址
    • 后一个客户端的 fd 会覆盖前一个，导致只有最后一个客户端正常工作
    • malloc 新空间保证每个线程有独立的客户端信息
  3. 客户端为什么也需要多线程？
    • 实现全双工通信：一个线程发数据，一个线程收数据
    • 单线程下 send 和 recv 会互相阻塞
  4. pthread_detach 的作用？
    • 将线程变为分离状态，退出后自动回收资源
    • 服务器中每个客户端线程通常 detach，不需要 join

6.3 多客户端通信

  1. 聊天室/多客户端互发的核心架构？
    • 服务端只做数据中转，不处理业务逻辑
    • 客户端A发消息 → 服务端 → 广播给其他所有客户端
  2. sscanf 的用法和格式控制符？
    • 从字符串按格式解析数据
    • %d 整数、%s 字符串、%[^#] 读取直到 # 为止
    • 格式必须与数据完全一致才能正确解析
  3. 消息确认机制的作用？
    • 服务端收到消息后回发确认（如 “编号#OK#”）
    • 客户端知道消息已被准确接收，类似微信”已读”状态
  4. 多线程下操作共享客户端数组需要注意什么？
    • 需要互斥锁保护，避免竞态条件
    • 添加、删除、广播客户端时都要加锁

6.4 多进程与共享内存

  1. 多进程服务器为什么用共享内存管理客户端状态？
    • 进程间地址空间独立，无法直接共享数据
    • 共享内存映射到所有进程的地址空间，实现状态共享
  2. 共享内存的操作流程？
    • ftok → shmget → shmat → 读写 → shmdt → shmctl(IPC_RMID)
  3. 多进程下操作共享内存需要注意什么？
    • 需要信号量保护，避免多个进程同时写入导致竞态条件
    • 共享内存不会自动删除，需要显式调用 shmctl(IPC_RMID)
